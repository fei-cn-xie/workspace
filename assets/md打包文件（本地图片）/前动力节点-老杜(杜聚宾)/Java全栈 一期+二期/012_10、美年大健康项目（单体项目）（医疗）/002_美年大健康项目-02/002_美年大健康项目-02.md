# 配置 Spring Cache

Spring Cache 本身不是一个缓存实现，而是一个管理缓存的抽象框架（缓存抽象层）

Spring Cache 是一个**缓存抽象层**，它：

- ✅ **定义了一套统一的缓存操作API**（注解和接口）
- ✅ **整合多种缓存实现**，让你可以无缝切换
- ❌ **不提供具体的缓存存储能力**

## 缓存什么数据

在大型网站中，将首页等高频访问数据缓存于内存是提升性能的关键手段。这避免了每次请求都查询数据库，从而极大加快响应速度。

鉴于内存容量有限，缓存策略需围绕业务核心设计。例如，电商缓存热门商品，新闻站缓存当日新闻。

我们的大健康体检项目将“**热门体检套餐**”等核心数据优先缓存，以实现最优的性能提升。

## Spring Cache 的使用

在 `<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">application.yml</font>` 配置文件中，我们需要设置 Spring Cache 的相关属性。

Spring Cache 支持多种缓存实现，如 Redis、Ehcache 等。

在本项目中，我们选用普及度更高、性能更优的 Redis 作为缓存方案。

```yaml
spring:
  cache:
    type: redis
    redis:
      time-to-live: 2592000000  # 30天缓存时间（单位：毫秒）
```

我们可以使用 `<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">@Cacheable</font>` 注解将查询结果缓存起来。Spring Cache 基于 Redis 构建的缓存采用 Key-Value 结构，其中 Value 即为查询结果，而 Key 则可以通过注解的 `<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">key</font>` 属性进行自定义。

```java
// Redis 缓存就是一个大柜子，里面有很多抽屉。
// cacheNames：就是每个抽屉的名字。
// key：就是每个抽屉里具体文件的文件名。
@Override
@Cacheable(cacheNames = "goods", key = "#id")
public HashMap searchById(int id) {
    //根据商品ID查询商品详情信息
}
```

`cacheNames`属性和 `value`属性是等价的，用哪个都可以：

![cb27420d-bf43-4cec-89c0-b395bcc95d01.png](images/IzLEbuXSKofbxQxzgZYcvMslnlg.png)

该Service方法用于更新商品信息。方法上的`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">@CacheEvict</font>`注解会在执行后，清除指定商品的缓存。

具体来说，它会根据Key（如商品ID）定位并删除Redis中对应的缓存数据，而其他商品的缓存则不受影响，依旧保留。

```java
@Override
@Transactional
@CacheEvict(cacheNames = "goods", key = "#entity.id")
public int update(GoodsEntity entity) {
    //更新某个商品的信息
}
```

# 全局异常处理

实际开发中，异常的处理通常是：

1. 后端用日志框架记录异常的详细信息。
2. 返回给前端一个简单的异常描述信息。

## 自定义异常

自定义系统的业务异常，创建 `exception`包，包下新建 `HisException`类，用来定义业务异常：

```java
package com.jkweilai.meinian.api.exception;

import lombok.Data;

@Data
public class HisException extends RuntimeException {
    private String msg;
    private int code = 500;

    // 捕获到其他异常时直接包装
    public HisException(Exception e) {
        super(e);
        this.msg = "执行异常";
    }
    // 简单的业务逻辑错误提示
    public HisException(String msg) {
        super(msg);
        this.msg = msg;
    }
    // 既有自定义错误信息，又要保留原始异常栈
    public HisException(String msg, Throwable e) {
        super(msg, e);
        this.msg = msg;
    }
    // 需要指定特定错误码的业务异常
    public HisException(String msg, int code) {
        super(msg);
        this.msg = msg;
        this.code = code;
    }
    // 最完整的场景 - 既有错误码、自定义信息，又保留原始异常
    public HisException(String msg, int code, Throwable e) {
        super(msg, e);
        this.msg = msg;
        this.code = code;
    }
}
```

## 全局异常处理

创建`config`包，在该包下新建 `ExceptionAdvice`类，编写以下代码：

```java
package com.jkweilai.meinian.api.config;

import cn.dev33.satoken.exception.NotLoginException;
import cn.hutool.json.JSONObject;
import com.jkweilai.meinian.api.exception.HisException;
import lombok.extern.slf4j.Slf4j;
import org.springframework.http.HttpStatus;
import org.springframework.http.converter.HttpMessageNotReadableException;
import org.springframework.validation.BindException;
import org.springframework.web.HttpRequestMethodNotSupportedException;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.ResponseBody;
import org.springframework.web.bind.annotation.ResponseStatus;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import org.springframework.web.multipart.support.MissingServletRequestPartException;

@Slf4j
@RestControllerAdvice
public class ExceptionAdvice {
    /*
     * 捕获异常，并且返回500状态码
     */
    @ResponseBody // 响应JSON字符串到前端
    @ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR) // 状态码500
    @ExceptionHandler(Exception.class) // 除了没登录异常，其它异常都走这个处理器
    public String exceptionHandler(Exception e) {
        JSONObject json = new JSONObject();
        if (e instanceof HttpMessageNotReadableException ex) {
            // 当HTTP请求体（Body）的数据格式错误或无法解析时，就会发生此异常
            log.error("error", ex);
            json.set("error", "请求未提交数据或者数据有误");
        } else if (e instanceof MissingServletRequestPartException ex) {
            // 当请求中缺少预期的文件（@RequestPart）或表单字段时，就会发生此异常
            log.error("error", ex);
            json.set("error", "请求提交数据错误");
        } else if (e instanceof HttpRequestMethodNotSupportedException ex) {
            // 当客户端使用了一个该URL不支持的HTTP方法（如用GET访问只支持POST的接口）时，就会发生此异常。
            log.error("error", ex);
            json.set("error", "HTTP请求方法类型错误");
        } else if (e instanceof BindException ex) {
            // 当请求参数绑定到Java对象（如使用@RequestBody或@ModelAttribute）失败时，就会发生此异常
            String defaultMessage = ex.getFieldError().getDefaultMessage();
            log.error(defaultMessage, ex);
            json.set("error", defaultMessage);
        } else if (e instanceof MethodArgumentNotValidException ex) {
            // 没有通过后端验证产生的异常
            // 当使用 @Valid 注解校验请求体参数失败时，就会发生此异常
            json.set("error", ex.getBindingResult().getFieldError().getDefaultMessage());
        } else if (e instanceof HisException ex) {
            // 处理业务异常
            log.error("执行异常", e);
            json.set("error", ex.getMsg());
        } else {
            // 处理其余的异常
            log.error("执行异常", e);
            json.set("error", "执行异常");
        }
        return String.valueOf(json);
    }

    /*
     * 捕获异常，并且返回401状态码
     */
    @ResponseBody // 响应JSON给前端
    @ResponseStatus(HttpStatus.UNAUTHORIZED) // 状态码：401
    @ExceptionHandler(NotLoginException.class) // 当Sa-Token检测到用户没有登录时就会抛出这个异常
    public String unLoginHandler(Exception e) {
        JSONObject json = new JSONObject();
        json.set("error", e.getMessage());
        return String.valueOf(json);
    }
}
```

# 配置线程池 ThreadPool

我们项目中有一个功能是**生成体检报告**，这个过程非常慢，如果不启用异步处理，用户体验不好。我们先来配置一下线程池。然后在后续编写程序时，如果某个方法需要采用异步方式执行，则在该方法上直接添加一个注解就行了，这样这个方法会被自动委派给线程池中的空闲线程来执行。

**思考一个问题：Tomcat 服务器本身不是支持多线程的吗？为什么还要自己配置线程池？高并发的情况下，如果要生成体检报告，直接使用 Tomcat 服务器的线程不行吗？答案是：不一样。**

**本质上，咱们配置的线程池的线程和 Tomcat 服务器线程池的线程是一样的。但是他们在“资源占用”层面是不一样的，一个“背负着HTTP上下文的Tomcat线程”和一個“轻量级的异步线程”是不等价的。前者在耗时任务中，会造成关联资源的严重滞留和浪费。另外他们的职责也不一样，Tomcat 服务器的线程池的线程用来接收前端发过来的请求，SpringBoot 线程池负责处理后台业务！**

## 配置线程池

```java
package com.jkweilai.meinian.api.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.task.AsyncTaskExecutor;
import org.springframework.scheduling.concurrent.ThreadPoolTaskExecutor;

import java.util.concurrent.ThreadPoolExecutor;

@Configuration
public class ThreadPoolConfig {

    @Bean("AsyncTaskExecutor")
    public AsyncTaskExecutor taskExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();

        // 核心线程数一般定义CPU核数的2倍。
        // 设置核心线程数
        executor.setCorePoolSize(8);
        // 设置最大线程数
        executor.setMaxPoolSize(16);
        // 设置队列容量（线程没有空闲的就排队，这个设置排队容量）
        executor.setQueueCapacity(1000);
        // 设置线程活跃时间（秒）60秒没有活跃，杀死该线程
        executor.setKeepAliveSeconds(60);
        // 线程名称的前缀，线程前缀名随意
        executor.setThreadNamePrefix("task-");
        // 设置拒绝策略
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
        //初始化线程池
        executor.initialize();
        return executor;
    }

}
```

当线程池的任务队列已满时，它将按照预设的拒绝策略处理新提交的任务。以下是几种常见的拒绝策略及其行为：

- **AbortPolicy（中止策略）**
直接抛出 `RejectedExecutionException` 异常，阻止系统继续执行。这是线程池的**默认拒绝策略**。
- **CallerRunsPolicy（调用者运行策略）**
将任务回退给提交任务的线程（通常是主线程）来执行。这种策略能确保任务不被丢弃，适用于不允许任务丢失的场景。例如生成体检报告，一旦放弃任务将导致报告无法生成，此时可采用此策略。
- **DiscardOldestPolicy（丢弃最老任务策略）**
移除队列中最早进入的任务，然后将当前任务加入队列，以腾出空间执行新任务。
- **DiscardPolicy（静默丢弃策略）**
直接丢弃无法处理的任务，既不执行也不抛出异常，适用于对任务完整性要求不高的场景。

## 开启异步线程功能

SpringBoot 的异步功能让我们无需手动操作线程池。我们只需定义一个任务，并使用 `<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">@Async</font>` 注解标记，SpringBoot 就会自动安排线程池来执行它。主线程就像把任务“扔进”线程池后便挂挡就走，不会原地等待结果，因此被称为“异步”。

在MeinianApiApplication主类的声明中，添加上@EnableAsync注解，就可以开启异步线程功能了

```java
package com.jkweilai.meinian.api;

import org.mybatis.spring.annotation.MapperScan;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.boot.web.servlet.ServletComponentScan;
import org.springframework.context.annotation.ComponentScan;
import org.springframework.scheduling.annotation.EnableAsync;

@EnableAsync // 开启异步线程
@ServletComponentScan

@ComponentScan("com.jkweilai.*")
@MapperScan(basePackages = "com.jkweilai.meinian.api.db.mapper")
@SpringBootApplication
public class MeinianApiApplication {

    public static void main(String[] args) {
        SpringApplication.run(MeinianApiApplication.class, args);
    }

}
```

要使用异步线程，我们只需在一个方法上添加 `<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">@Async</font>` 注解。该方法在执行时会被自动提交到线程池，由空闲线程处理。这意味着像生成体检报告这样的耗时任务将与主线程分离，不会阻塞主流程。

```java
@Service
@Slf4j
public class CheckupWorkAsync {

    // 这个方法会交给异步线程执行。
    @Async("AsyncTaskExecutor")
    public void createReport(Integer id) {
        // 检查哪些人的报告数据已经准备完毕，然后生成体检报告
    }
}
```

# 统一响应体封装

在后续开发中，我们将编写大量返回JSON数据的Web方法。为了统一响应格式，我们需要预先定义JSON对象的公共结构。由于使用了`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">@RestController</font>`注解，方法的返回值会被自动转换为JSON，因此我们只需创建一个统一的响应封装类，并让所有Web方法都返回该类的实例即可。

考虑到不同方法返回的业务数据各不相同，响应体需要具备动态性。为此，我们可以选择一个灵活的结构作为基础。在本项目中，我们将使用`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">HashMap</font>`作为父类，在`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">com.jkweilai.meinian.api.common</font>`包下创建这个名为`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">R</font>`的响应封装类。

```java
package com.jkweilai.meinian.api.common;

import org.apache.http.HttpStatus;

import java.util.HashMap;
import java.util.Map;

/**
 * 统一API响应结果封装类
 * 继承自HashMap，提供链式操作，用于规范所有Controller方法的返回格式
 */
public class R extends HashMap<String, Object> {

    /**
     * 默认构造器：初始化一个成功的响应
     * 设计意图：默认创建即表示成功，符合大多数成功场景，减少冗余设置。
     */
    public R() {
        // 默认创建的R对象中包含了公共的属性
        put("code", HttpStatus.SC_OK);
        put("msg", "success");
    }

    /**
     * 重写put方法，支持链式调用
     * 例如：r.put("data", data).put("token", token);
     * 设计意图：提升代码的流畅度和可读性，便于动态添加多个自定义字段。
     *
     * @param key   键
     * @param value 值
     * @return 当前R对象自身
     */
    @Override
    public R put(String key, Object value) {
        super.put(key, value);
        // 返回自己，用于链式调用
        return this;
    }

    /**
     * 创建一个表示【成功】的响应对象（无附加数据）
     * 设计意图：用于操作成功但无需返回业务数据的场景，如新增、删除、修改操作。
     *
     * @return 默认的成功响应对象
     */
    public static R ok() {
        return new R();
    }

    /**
     * 创建一个表示【成功】的响应对象，并自定义成功消息
     * 设计意图：在成功的基础上，提供更具体的成功提示信息。
     *
     * @param msg 自定义的成功消息
     * @return 带有自定义消息的成功响应对象
     */
    public static R ok(String msg) {
        R r = new R();
        r.put("msg", msg);
        return r;
    }

    /**
     * 创建一个表示【成功】的响应对象，并批量添加数据
     * 设计意图：当需要返回多个键值对数据时，可以传入一个Map，避免多次调用put方法。
     *
     * @param map 包含多个键值对数据的Map
     * @return 包含了指定Map所有数据的成功响应对象
     */
    public static R ok(Map<String, Object> map) {
        R r = new R();
        r.putAll(map);
        return r;
    }

    /**
     * 创建一个表示【错误】的响应对象，并指定错误码和错误信息
     * 设计意图：提供最灵活的错误创建方式，允许自定义业务错误码和错误信息。
     *
     * @param code 错误码（通常使用HTTP状态码或自定义业务状态码）
     * @param msg  错误信息
     * @return 错误响应对象
     */
    public static R error(int code, String msg) {
        R r = new R();
        // 覆盖默认的成功状态码和消息
        r.put("code", code);
        r.put("msg", msg);
        return r;
    }

    /**
     * 创建一个表示【错误】的响应对象，使用默认错误码（500）
     * 设计意图：简化错误创建，在仅需提供错误信息而错误码可默认为500时使用。
     *
     * @param msg 错误信息
     * @return 错误响应对象
     */
    public static R error(String msg) {
        return error(HttpStatus.SC_INTERNAL_SERVER_ERROR, msg);
    }

    /**
     * 创建一个表示【错误】的响应对象，使用默认错误码和错误信息
     * 设计意图：作为最后的兜底方案，在捕获到未知异常时返回，避免暴露系统内部细节。
     *
     * @return 使用默认错误码和信息的错误响应对象
     */
    public static R error() {
        return error(HttpStatus.SC_INTERNAL_SERVER_ERROR, "未知异常，请联系管理员");
    }
}
```

# 创建自签名 HTTPS 数字证书

## 为什么要创建 HTTPS 数字证书

我们之前提到过，在 Sa-Token 权限框架中会生成 Token 令牌，令牌在网络中被黑客窃取的话，黑客就可以使用令牌冒充我们的身份去访问系统。因此我们的令牌在网络传输中需要以加密的形式传输。所以我们要使用 HTTPS 安全协议进行传输。

**因为 HTTP 是透明的，Token 在里面就像大声喊出来的密码，沿途所有坏人都能听见并偷走。而 HTTPS 是加密的私人电话，只有通话的双方能听懂。为了让 Token 从用户浏览器到后端 API 的整个旅途都安全，我们必须全程使用 HTTPS 这个‘加密电话’。**

## 创建自签名数字证书

开通HTTPS服务必须配置数字证书。数字证书应该由公共信任的（CA 机构）签发。开发阶段没必要，使用自签名证书模拟一下就行。

在命令行界面执行下面的指令，生成一个365天有效期的数字证书文件。

```bash
keytool -genkey -alias jetty -dname "CN=demo,OU=demo,O=demo,L=BeiJing,ST=BeiJing,C=CN" -storetype PKCS12 -keyalg RSA -keysize 2048 -keystore keystore.p12 -validity 365
```

编写测试的 Controller，新建 `HttpsTestController`，编写以下代码：

```java
package com.jkweilai.meinian.api.controller;

import com.jkweilai.meinian.api.common.R;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
// 为什么需要手动指定以json格式响应？默认的响应格式是json，为什么还需要指定？
// 问题根源是支付 starter 包引入了 XML 支持，导致 Spring Boot 自动配置了 XML 消息转换器。
@RequestMapping(value = "/test", produces = "application/json")
public class HttpsTestController {

    @GetMapping("/ssl")
    public R test(){
```

### 注意事项

由于我们尚未实现登录功能，浏览器的 storage 无法自动保存令牌和权限信息。因此，我们可以手动向 storage 中添加模拟数据。如果不这样做，当你访问人员管理页面时，Vue 路由会检测到 storage 中没有有效数据，判定你尚未登录，从而自动跳转到登录页面。

要想访问资源，需要向 `<font style="color:rgb(15, 17, 21);">localStorage</font>`中写入两个数据：

1. token：随便写一个就行
2. permissions：这个需要写入 `[ROOT]`

**你这里可能会有疑问？如果在 **`**<font style="color:#DF2A3F;">storage</font>**`**中可以直接写如 token 和 permissions 的话，这个系统的权限不就没用了吗？**

- **并不是这样的，首先我们这样做是为了骗过浏览器，便捷我们前端项目的开发。**
- **实际项目在运行时，后端服务器会校验你前端提交过来的 token 对不对。另外后端系统也会动态查询你真实的权限，**
- **从纯前端视角来看，向 storage 中写入了 permissions 为 [ROOT] ，黑客确实能看到页面元素了，但无法获得真实的权限，数据接口全部访问失败，真实数据永远拿不到。**

# 用户密码加密

## 密码安全发展史

密码发展史在攻击和防御之间不断演变。没有绝对的安全。只有更安全。

1. 明文存储密码：这是最初密码的形态，黑客只要能获取到这个明文，即可登录系统。或者公司的数据库管理员离职了，把密码信息导出来拿走了。密码采用明文存储简直是裸奔。
2. 后来出现了哈希算法，哈希是不可逆的，一个好的密码应该是不可逆的。那大家可能会有一个疑问：那怎么验证用户输入的密码是否正确呢？非常简单，只要接收到用户表单提交的密码，将这个密码经过同一个哈希算法得出结果，拿这个结果和数据库表中存储的密码进行比对即可。常见的哈希算法有 MD5，SHA 等。不过这种方式也是不安全的，因为黑客自己搞了一个哈希字典，这个哈希字典又被称为彩虹表，彩虹表中是大量的随意的字符串的组合（可以看作是黑客猜测的密码），每个字符串都进行哈希得出一个结果，黑客拿着他非法获取的用户密码和彩虹表中的哈希值进行比对，只要比对成功了，他就知道这个密码的明文是什么了。得到明文就可以轻松登录你的系统了。
3. 随着黑客的攻击手段升级，简单的哈希已经无法解决安全问题了，因此为了防御，出现了“哈希再哈希”，什么意思呢？就是将密码进行哈希后得到一个字符串，这个字符串的长度一般是 32 个，然后对这 32 个长度的哈希值再进行哈希，又得到一个全新的 32 个长度的哈希值，然后将这个值最终存储到数据库中，但这种方式黑客也能破解，它仍然是利用彩虹表，他拿着你 32 个长度的哈希值经过彩虹表的查询一看结果仍然是一个 32 个长度的字符串，因此他断定这个肯定还是一个哈希值，于是再继续查找彩虹表，最终找到你的明文密码。
4. 为了增强防御，后来出现了一种方式叫做加盐，给我们的明文密码前或后或者前后添加随机的字符串（**将随机字符串存储到用户表中**，每个用户信息中都有这些随机字符串，等待校验的时候使用，没关系，这个随机字符串暴露给黑客，也没有关系，因为他不知道你的明文密码是什么），然后再对这个整体的字符串进行哈希。这种算法最终的效果是：张三和李四的密码虽然是相同的，但是存储到数据库表中的密文是不同的。如果黑客破解，就需要给每个用户都准备一个单独的彩虹表（可想而知，这个破解难度是非常大的）。不过，在这种情况下，仍然没有绝对的安全。
5. 后来为了让黑客的破解成本提高，引入了慢哈希，也就是故意让哈希算法的执行速度变慢，假设之前一个哈希计算的过程是 1 秒，现在我让哈希计算的过程提升到 10 秒，虽然会折损系统的性能，影响用户的体验，但对于安全级别较高的系统来说，这一权衡是值得的。其中 Bcrypt 和 Argon2 都是典型的、被广泛推荐的慢哈希函数。

我们的系统没必要使用慢哈希，现在我把我们系统的加密算法公开给大家，我是这样做的：将用户名进行哈希，得出一个字符串，然后取字符串的前 6 位和后 3 位，然后和用户的明文密码进行拼接，然后再哈希，然后转大写，存储到数据库表当中。哈希采用 MD5。接下来我们来编写一下登录逻辑：验证用户名和密码是否正确。

## 登录的 service 程序

创建 `service`包，然后在该包下新建 `SysUserService`接口。然后编写以下代码：

```java
package com.jkweilai.meinian.api.service;

import java.util.Map;

public interface SysUserService {

}
```

编写 service 接口的实现类，代码如下：

```java
package com.jkweilai.meinian.api.service.impl;

import cn.hutool.core.map.MapUtil;
import cn.hutool.core.util.StrUtil;
import cn.hutool.crypto.digest.MD5;
import com.jkweilai.meinian.api.db.mapper.SysUserMapper;
import com.jkweilai.meinian.api.service.SysUserService;
import jakarta.annotation.Resource;
import org.springframework.stereotype.Service;

import java.util.Map;

@Service
public class SysUserServiceImpl implements SysUserService {

    @Resource
    private SysUserMapper sysUserMapper;

    @Override
    public Integer login(Map<String, Object> userMap) {
        // 获取用户提交的用户名和密码
        String username = MapUtil.getStr(userMap, "username");
        String password = MapUtil.getStr(userMap, "password");
        // 获取MD5对象
        MD5 md5 = MD5.create();
        // 对用户名进行哈希
        String usernameMD5 = md5.digestHex(username);
        // 获取前6位
        String usernameMD5Start = StrUtil.subWithLength(usernameMD5, 0, 6);
        // 获取后3位
        String usernameMD5End = StrUtil.subSuf(usernameMD5, usernameMD5.length() - 3);
        // 拼接密码
        password = usernameMD5Start + password + usernameMD5End;
        // 经过哈希,然后转换大写
        String pwd = md5.digestHex(password).toUpperCase();
        // 验证用户名和密码
        return sysUserMapper.selectByUsernameAndPassword(username, pwd);
    }
}
```

这段代码是将用户登录表单提交过来的密码进行一系列运算之后得到一个字符串，然后拿这个字符串和底层数据库中真实存储的密码进行比对，一致则登录成功。

```java
import cn.hutool.core.bean.BeanUtil;
import com.jkweilai.meinian.api.common.R;
import com.jkweilai.meinian.api.controller.form.LoginForm;
import com.jkweilai.meinian.api.service.SysUserService;
import jakarta.annotation.Resource;

import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import java.util.List;
import java.util.Map;

@RestController
@RequestMapping("/mis/user")
public class UserController {

    @Resource
    private SysUserService sysUserService;

    @PostMapping("/login")
    public R login(@RequestBody @Valid LoginForm loginForm){
        // 将loginForm转换成Map
        Map<String, Object> loginMap = BeanUtil.beanToMap(loginForm);
        // 调用service登录
        Integer userId = sysUserService.login(loginMap);
        if (userId != null) {
            // 登录成功，生成令牌
            StpUtil.login(userId, "Web");
            // 获取令牌
            String token = StpUtil.getTokenValueByLoginId(userId, "Web");

            // 响应
            return R.ok().put("result", true).put("token", token).put("permissions", permissions);

        // 登录失败
        return R.ok().put("result", false);
    }
}
```

```typescript
// 导入axios
import axios from 'axios';

// 登录函数
async function login(){

    // 验证用户名是否合法
    if(!isUsername(loginInfo.username)){
        proxy.$message({
            // 提示信息
            message: "用户名格式错误",
            // 错误信息，以红色显示
            type: 'error',
            // 持续1200毫秒
            duration: 1200
        });

            // 提示信息
            message: "密码格式错误",
            // 错误信息，以红色显示
            type: 'error',
            // 持续1200毫秒
            duration: 1200
        });
    } else {
        // 封装数据
        const loginData = {
            username: loginInfo.username,
            password: loginInfo.password
        };
        // 配置
        const config = {
            headers: {
                'Content-Type': 'application/json'
            }
        };

        const data = response.data;

                duration: 1200
            });
        }
    }
}
```

```java
@Transactional
public int modifyPassword(Map<String, Object> param) {
    // 获取userId
    int userId = MapUtil.getInt(param, "userId");
    // 获取用户名

    oldPassword = md5.digestHex(oldPassword).toUpperCase();

    // 经过哈希,然后转换大写
```

```sql
SELECT u.username,
```

**我们来分析一下这个 SQL 语句的执行顺序：**

1. `FROM sys_user u`：从 sys_user 表中查询
2. `WHERE u.real_name LIKE "%管理员%";`：先找出名字中含有管理员的用户信息（这个结果可能是多个）
3. 执行完第二步之后，查询结果可能是多个用户，然后一个用户一个用户过，假设这个时候过的是第一个用户：
  1. 取出第一个用户的用户名。
  2. （子查询）取出**这个用户**关联的角色集。
  3. 取出第二个用户的用户名。
  4. （子查询）取出**这个用户**关联的角色集。
  5. 以此类推。直到结束。

接下里，我们来推演一下，当查询时，用户输入的查询条件如下，并且每页显示 10 条记录，显示第 1 页的 SQL 语句该怎么写？

用户输入以下查询条件：

1. 姓名：管理员 (模糊查询)
2. 性别：男
3. 部门：运营管理中心（运营管理中心对应的部门 id=1）
4. 状态：在职（也就是 user_status = 1）
5. 角色：部门经理（部门经理对应的 role_id=2）

SQL 语句如下：

```sql
SELECT u.user_id,u.real_name,u.gender,u.mobile,u.hire_date,d.dept_name,
       (SELECT GROUP_CONCAT(a.role_name SEPARATOR ",") 
        FROM sys_role a
        WHERE JSON_CONTAINS(u.role_ids, CONVERT(a.role_id, CHAR))) AS roles
FROM sys_user u
left JOIN sys_department d on u.dept_id = d.id
WHERE 
  u.gender = '男' 
  and d.id = 1
  and u.user_status = 1
  and u.real_name LIKE "%管理员%"
  and EXISTS (
    SELECT 1 FROM sys_role r 
    WHERE JSON_CONTAINS(u.role_ids, CAST(r.role_id AS JSON))
    AND r.role_id = 2
  )
limit 0, 10;
```

![08ee1d9f-8fc8-42ca-857b-f17c073ea741.png](images/PWHPbLuYyoxACixckFWcDDianGd.png)

1. **EXISTS 后面小括号中的子查询，如果查询结果条数=0，则EXISTS 返回 false。**
2. **如果查询条件>0，则EXISTS 返回 true。**
3. **以上 SQL 中 EXISTS 的作用是：判断当前用户是否存在 2 号角色。（因为我们的查询条件中可以根据角色查询）**

## 封装分页数据

最终查询的结果要返回给前端，接下来封装 `PageResult`类，先来分析一下，需要返回给前端的分页数据包括哪些属性？

1. 总记录条数：total
2. 每页显示记录条数：pageSize（这个不需要返回给前端，用它只是为了计算总页数）
3. 当前页码：pageNo（这个也不需要返回给前端，用它只是为了计算总页数）
4. 总页数：pages（如果前端使用的 ElementPlus 提供的分页组件，这个属性也是不需要提供的。它会自动计算。）
5. 当前页数据：records

代码如下：在 common 包下新建 PageResult 类

```java
package com.jkweilai.meinian.api.common;

import lombok.Data;

import java.util.List;

/**
 * 分页数据
 *
 * @param <T>
 */
@Data
public class PageResult<T> {
    // 总记录条数
    private Long total;
    // 每页显示多少条(这个属性的存在并不是为了返回给前端，而是为了计算总页数。)
    private Integer pageSize;
    // 当前页码(这个属性的存在并不是为了返回给前端，而是为了计算总页数。)
    private Integer pageNo;
    // 总页数(其实这个总页数也不需要提供，因为我们前端使用的是ElementPlus提供的分页组件，它是可以自动计算总页数的。)
    // 咱们这里编写的分页对象是较为通用的分页对象。
    private Integer pages;
    // 当前页数据
    private List<T> records;

    // 虽然有5个属性，但是只需要传递4个参数，因为总页数可以动态计算。
    public PageResult(Long total, Integer pageSize, Integer pageNo, List<T> records) {
        this.total = total;
        this.pageSize = pageSize;
        this.pageNo = pageNo;
        this.pages = (int) (total % pageSize == 0 ? total / pageSize : total / pageSize + 1);
        this.records = records;
    }
}
```

```typescript
// 分页查询
const form: Ref = ref(null);
async function searchHandle() {
    let valid = await form.value.validate();
    if (valid) {
        // 清理验证结果（清除验证错误提示）
        form.value.clearValidate();
        data.pageIndex = 1;
        //加载分页记录
        loadPageData();
    }
}
// 加载分页数据
async function loadPageData(){
    // 显示加载进度条
    data.loading = true;

    // 加载用户分页数据
    // 查询条件：从另一个响应式对象 dataForm 上获取数据封装查询条件
    const queryCondition = {
        pageNo: data.pageIndex,
        pageSize: data.pageSize,
        realName: dataForm.name,
        gender: dataForm.sex,
        roleId: dataForm.role,
        deptId: dataForm.deptId,
        userStatus: dataForm.status
    }

    // token放到headers中
    const config = {
        headers: {
            'satoken': localStorage.getItem("token")
        }
    };

    // 发送ajax post请求
    const response = await axios.post('/meinian-api/mis/user/pageQuery', queryCondition, config);

    // 将响应回来的用户列表数据放到响应式对象的对应属性上
    const records = response.data.pageResult.records;
    for(let record of records){
        if(record.userStatus == 1){
            record.userStatus = '在职';
        }else if(record.userStatus == 2){
            record.userStatus = "离职";
        }
    }
    data.dataList = records;
    // 更新总记录条数
    data.totalCount = response.data.pageResult.pages;

    // 隐藏加载进度条
    data.loading = false;
}


// 页面打开的时候就加载。
loadPageData();
```

## 一个坑

当提交的数据是数字 0 时，假设提交了 roleId 是 0 数字，到 Java 程序中的类型是 int/Integer，那么这个会导致以下 mybatis 的配置出现问题：

```xml
<!-- MyBatis OGNL表达式中，当数字0与空字符串''比较时，
OGNL会将空字符串转换为数字0，导致0 == ''为true，
从而使条件roleId != ''判断失败。 -->
<if test="roleId != null and roleId != ''">
    and EXISTS (
        SELECT 1 FROM sys_role r
        WHERE JSON_CONTAINS(u.role_ids, CAST(r.role_id AS JSON))
        AND r.role_id = #{roleId}
    )
</if>
```

因此我们这里需要将以上配置修改为：（**两个位置都要修改，一个是查询总记录条数，一个是查询数据**）

```xml
<if test="roleId != null">
    and EXISTS (
        SELECT 1 FROM sys_role r
        WHERE JSON_CONTAINS(u.role_ids, CAST(r.role_id AS JSON))
        AND r.role_id = #{roleId}
    )
</if>
```

包括部门编号位置的判断也需要修改。

## 前端实现修改功能

### 弹出修改窗口

当用户点击分页查询结果列表中某条记录后面的 **修改** 按钮时，弹出修改用户的窗口，在窗口的表单中显示当前用户的详细信息。实现思路：

1. 点击修改按钮，将当前用户的 id 传递给回调函数。
2. 回调函数中先将模型层的 dialog.dataForm.id 的值赋上去，因为这是修改操作，用户 id 必须提供。
3. 然后将 dialog.update 修改为 true，表示现在是修改操作，弹窗必须是一个修改用户的窗口。
4. 发送 ajax 请求，根据 id 获取用户信息，将用户信息填充到响应式对象上即可。
5. 然后设置 dialog.visible 为 true，显示窗口。

**代码如下：**

调用回调的时候传递用户的 id，如下：

```plaintext
<el-button type="text" v-if="proxy.isAuth(['ROOT', 'USER:UPDATE'])" @click="updateHandle(scope.row.userId)">修改</el-button>
```

注意控制权限，不是所有人都能修改。另外，通过 `scope.row.userId`来获取当前这条记录的用户的 id。

**特别强调：**不是 `scope.row.id`，是 `scope.row.userId`，因为分页查询返回的用户列表数据中每个用户对象中主键属性名为 userId。

继续编写回调函数：

```typescript
async function updateHandle(userId){
    dialog.dataForm.id = userId;
    dialog.update = true;

    // 显示弹窗（一定要先渲染窗口，后填充数据）
    dialog.visible = true;
    await nextTick();
    
    // 准备数据
    const json = {
        userId: userId
    };
    // 准备token
    const config = {
        headers: {
            'satoken': localStorage.getItem('token')
        }
    };
    // 发送ajax请求
    const response = await axios.post('/meinian-api/mis/user/findUserById', json, config);
    const result = response.data.result;
    dialog.dataForm.realName = result.realName;
    dialog.dataForm.gender = result.gender;
    dialog.dataForm.mobile = result.mobile;
    dialog.dataForm.email = result.email;
    dialog.dataForm.hireDate = result.hireDate;
    // 将后端返回的json字符串转换成对象。
    dialog.dataForm.role = JSON.parse(result.roleIds);
    dialog.dataForm.deptId = result.deptId;
}
```

```typescript
function deleteHandle(userId){
    // 不管是用户是进行单个删除，还是批量删除，将userId封装到数组中，用于提交数据。
    const userIds = userId ? [userId] : data.selections.map(item => {
        return item.userId;
    });
    if(userIds.length == 0){
        proxy.$message({
            message: '请选择要删除的记录',
            type: 'warning',
            duration: 1200
        });
    }else{
        proxy.$confirm('确定要删除选中的记录吗?', '提示', {
            confirmButtonText: "确定",
            cancelButtonText: "取消",
            type: 'warning'
        }).then(async () => {
            // 发送ajax请求删除数据(发送delete请求和之前的get和post请求有区别。)
            const response = await axios.delete('/meinian-api/mis/user/remove', {
                data: {
                    userIds: userIds
                },
                headers: {
                    'satoken': localStorage.getItem("token")
                }
            });
            const rows = response.data.rows;
            if(rows > 0){
                proxy.$message({
                    message: "操作成功",
                    type: 'success',
                    duration: 1200,
                    onClose: () => {
                        // 重新加载当前分页数据
                        loadPageData();
                    }
                });
            }else{
                proxy.$message({
                    message: "删除失败",
                    type: 'warning',
                    duration: 1200,
                });
            }
        });
    }
}
```

```javascript
axios.get(url, config)

axios.post(url, data, config)
```

13. create_time：套餐创建时间

# 套餐管理分页 RESTful 接口开发

## 分析查询条件都有哪些

![4d404e88-1f5e-4ca4-b7f5-7e818ee8598f.png](images/HHqCbrMlMoyOOXxvEgMcpzTLnsd.png)

1. 查询哪张表？`med_exam_package`体检套餐表。比较简单因为只需要进行一次表连接。（套餐表和促销规则表连接。）
2. 查询条件包括 5 个：
  1. 根据套餐名称模糊查询，字段名是：`package_name`
  2. 根据套餐编号查询，字段名是：`package_code`
  3. 根据套餐类型查询，字段名是：`package_type`
  4. 根据展示区查询，字段名是：`category_id`
  5. 根据状态查询，字段名是：`status`

## 分析查询结果列都有哪些

![345885b5-f443-41ae-91e9-fe32122f28c1.png](images/Vg8Bbrdu8oe6auxLgKxcGcGmnKG.png)

需要查询的列包括：

1. 主键：字段名是 `id`
2. 套餐名称：字段名是 `package_name`
3. 套餐编号：字段名是 `package_code`
4. 原价：字段名是 `original_price`
5. 现价：字段名是 `current_price`
6. 销量：字段名是 `sales_volume`
7. 套餐类型：字段名是 `package_type`
8. 促销规则：字段名在 `promotion_rule`表中，字段名为：`rule_name`，需要让 `med_exam_package`表和 `promotion_rule`表连接，但需要左连接，因为有的体检套餐是没有促销规则的。连接条件：`ep.promotion_id = pr.rule_id`
9. 体检内容：字段名是 `exam_items`，判断规则，如果该字段不为空，则页面上 体检内容 那一列展示：有文档。
10. 状态：字段名是 `status`
11. 展示区 ID：字段名 `category_id`，虽然页面上不显示这一列，但是这一列后面有用。

初步的 SQL 语句我们基本上已经可以写出来了：

```sql
select
  ep.id,
  ep.package_name as packageName,
  ep.package_code as packageCode,
  ep.original_price as originalPrice,
  ep.current_price as currentPrice,
  ep.sales_volume as salesVolume,
  ep.package_type as packageType,
  pr.rule_name as ruleName,
  (ep.exam_items is not null) as hasDocument,
  ep.status,
  ep.category_id as categoryId
from
  med_exam_package ep
left join
  promotion_rule pr
on
  ep.promotion_id = pr.rule_id;
```

## 编写 Mapper 和 Mapper XML

编写 `MedExamPackageMapper`，在该接口中编写两个方法，一个是根据条件查询总记录条数，一个是根据查询条件获取查询结果：

```java
public interface MedExamPackageMapper {

    long selectCountByCondition(Map<String, Object> params);

    List<Map<String, Object>> selectPageByCondition(Map<String, Object> params);
}
```

编写 `MedExamPackageMapper.xml`文件，编写 SQL 语句，如下：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper
        PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.jkweilai.meinian.api.db.mapper.MedExamPackageMapper">

    <select id="selectCountByCondition" resultType="long">
        select
            count(*)
        from
            med_exam_package ep
        left join
            promotion_rule pr
        on
            ep.promotion_id = pr.rule_id
        <where>
            <if test="packageName != null and packageName != ''">
                and ep.package_name like concat('%', #{packageName}, '%')
            </if>
            <if test="packageCode != null and packageCode != ''">
                and ep.package_code = #{packageCode}
            </if>
            <if test="packageType != null">
                and ep.package_type = #{packageType}
            </if>
            <if test="categoryId != null">
                and ep.category_id = #{categoryId}
            </if>
            <if test="status != null">
                and ep.status = #{status}
            </if>
        </where>
    </select>

    <select id="selectPageByCondition" parameterType="Map" resultType="Map">
        select
            ep.id,
            ep.package_name as packageName,
            ep.package_code as packageCode,
            ep.original_price as originalPrice,
            ep.current_price as currentPrice,
            ep.sales_volume as salesVolume,
            ep.package_type as packageType,
            pr.rule_name as ruleName,
            (ep.exam_items is not null) as hasDocument,
            ep.status,
            ep.category_id as categoryId
        from
            med_exam_package ep
                left join
            promotion_rule pr
            on
                ep.promotion_id = pr.rule_id
        <where>
            <if test="packageName != null and packageName != ''">
                and ep.package_name like concat('%', #{packageName}, '%')
            </if>
            <if test="packageCode != null and packageCode != ''">
                and ep.package_code = #{packageCode}
            </if>
            <if test="packageType != null">
                and ep.package_type = #{packageType}
            </if>
            <if test="categoryId != null">
                and ep.category_id = #{categoryId}
            </if>
            <if test="status != null">
                and ep.status = #{status}
            </if>
        </where>
        order by ep.id asc
        limit #{startIndex}, #{pageSize}
    </select>
```

## 编写 Service 与实现

编写 `MedExamPackageService`接口，提供一个方法，代码如下：

```java
package com.jkweilai.meinian.api.service;

import com.jkweilai.meinian.api.common.PageResult;

import java.util.Map;

public interface MedExamPackageService {

    PageResult<Map<String,Object>> pageQueryByCondition(Map<String, Object> param);

}
```

编写 `MedExamPackageServiceImpl`实现类，实现方法，代码如下：

```java
package com.jkweilai.meinian.api.service.impl;

import cn.hutool.core.map.MapUtil;
import com.jkweilai.meinian.api.common.PageResult;
import com.jkweilai.meinian.api.db.mapper.MedExamPackageMapper;
import com.jkweilai.meinian.api.service.MedExamPackageService;
import jakarta.annotation.Resource;
import org.springframework.stereotype.Service;

import java.util.ArrayList;
import java.util.List;
import java.util.Map;

@Service
public class MedExamPackageServiceImpl implements MedExamPackageService {

    @Resource
    private MedExamPackageMapper medExamPackageMapper;

    @Override
    public PageResult<Map<String, Object>> pageQueryByCondition(Map<String, Object> param) {
        // 查询总记录条数
        long total = medExamPackageMapper.selectCountByCondition(param);
        // 最好不好准备一个null，准备一个初始化容量为0的List集合。
        List<Map<String, Object>> records = new ArrayList<>();
        // 如果记录数大于0才有必要进行下一步的查询
        if (total > 0) {
            records = medExamPackageMapper.selectPageByCondition(param);
        }
        // 每页显示的记录条数
        Integer pageSize = MapUtil.getInt(param, "pageSize");
        // 当前页码
        Integer pageNo = MapUtil.getInt(param, "pageNo");
        // 封装分页对象
        PageResult<Map<String, Object>> pageResult = new PageResult<>(total, pageSize, pageNo, records);
        // 返回分页对象
        return pageResult;
    }
}
```

## 编写 Controller 实现 RESTful 接口

创建 `MedExamPackageController`，编写分页接口，代码如下：

```java
package com.jkweilai.meinian.api.controller;

import cn.dev33.satoken.annotation.SaCheckPermission;
import cn.dev33.satoken.annotation.SaMode;
import cn.hutool.core.bean.BeanUtil;
import com.jkweilai.meinian.api.common.PageResult;
import com.jkweilai.meinian.api.common.R;
import com.jkweilai.meinian.api.controller.form.ExamPackagePageQueryForm;
import com.jkweilai.meinian.api.service.MedExamPackageService;
import jakarta.annotation.Resource;
import jakarta.validation.Valid;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import java.util.Map;

@RestController
@RequestMapping("/mis/goods")
public class MedExamPackageController {

    @Resource
    private MedExamPackageService medExamPackageService;

    @PostMapping("/pageQuery")
    @SaCheckPermission(value = {"ROOT", "GOODS:SELECT"}, mode = SaMode.OR)
    public R pageQuery(@RequestBody @Valid ExamPackagePageQueryForm form){
        Integer pageSize = form.getPageSize();
        Integer pageNo = form.getPageNo();
        Integer startIndex = pageSize * (pageNo - 1);
        Map<String, Object> param = BeanUtil.beanToMap(form);
        param.put("startIndex", startIndex);
        PageResult<Map<String, Object>> pageResult = medExamPackageService.pageQueryByCondition(param);
        return R.ok().put("pageResult", pageResult);
    }
}
```
