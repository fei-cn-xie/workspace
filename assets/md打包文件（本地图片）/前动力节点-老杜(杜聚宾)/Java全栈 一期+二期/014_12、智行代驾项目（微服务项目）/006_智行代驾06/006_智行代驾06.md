# 利用 AI 对司乘对话内容安全评级-保存订单监控统计信息

之前已经把司乘对话的文本内容保存到 HBase 中了。接下来我们使用 AI 技术对聊天内容进行安全评级。如果用人工监控司乘对话是不现实的，成本太高了，也雇不起那么多人。因此我们使用腾讯云数据万象服务对内容进行分析（腾讯云数据万象服务底层使用的就是人工智能）。腾讯云数据万象服务之前我们已经开通了。接下来，我们先去完成第一个功能：保存订单监控统计信息。

## 了解 `<font style="color:#000000;">order_monitoring</font>`表

在HBase中，`<font style="color:#000000;background-color:rgba(220, 240, 255, 0.3) !important;">order_monitoring</font>`表是用来保存订单的监控统计信息，比如说某个订单有多少个音频记录，司乘对话内容是什么安全等级的，有多少段对话需要人工审核等等

| **字段** | **类型** | **备注** |
| --- | --- | --- |
| id | BIGINT | 主键 |
| order_id | BIGINT | 订单号 |
| status | TINYINT | 状态（1 表示订单进行中，0 表示订单结束了） |
| records | INTEGER | 录音文件的数量 |
| safety | VARCHAR | 安全等级，安全值是 common |
| reviews | INTEGER | 需要人工审核的数量（数据万象审核不准时需要人工审核，这个字段记录的是需要人工审核的数量） |
| alarm | TINYINT | 是否报警（代表该订单有没有触发报警，1 表示没有触发，2 表示触发了） |
| create_time | DATE | 创建日期时间 |

## 编写异步线程任务类

![49dcb3b4-8876-410a-a67d-390b3618ef87.png](images/FLBNbMv6powxRfxIKclcqOitnfe.png)

数据万象的API文档（[https://cloud.tencent.com/document/product/460/61607](https://cloud.tencent.com/document/product/460/61607)）。

在`<font style="color:#000000;background-color:rgba(220, 240, 255, 0.3) !important;">com.example.zxds.nebula.task</font>`包中创建`<font style="color:#000000;background-color:rgba(220, 240, 255, 0.3) !important;">VoiceTextCheckTask.java</font>`类。

```java
package com.example.zxds.nebula.task;

import cn.hutool.core.codec.Base64;
import cn.hutool.core.map.MapUtil;
import cn.hutool.core.util.ArrayUtil;
import cn.hutool.core.util.StrUtil;
import com.example.zxds.common.exception.ZxdsException;
import com.example.zxds.nebula.db.dao.OrderMonitoringDao;
import com.example.zxds.nebula.db.dao.OrderVoiceTextDao;
import com.example.zxds.nebula.db.pojo.OrderMonitoringEntity;
import com.qcloud.cos.COSClient;
import com.qcloud.cos.ClientConfig;
import com.qcloud.cos.auth.BasicCOSCredentials;
import com.qcloud.cos.auth.COSCredentials;
import com.qcloud.cos.model.ciModel.auditing.AuditingJobsDetail;
import com.qcloud.cos.model.ciModel.auditing.SectionInfo;
import com.qcloud.cos.model.ciModel.auditing.TextAuditingRequest;
import com.qcloud.cos.model.ciModel.auditing.TextAuditingResponse;
import com.qcloud.cos.region.Region;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.scheduling.annotation.Async;
import org.springframework.stereotype.Component;
import org.springframework.transaction.annotation.Transactional;

import javax.annotation.Resource;
import java.util.*;

@Component
@Slf4j
public class VoiceTextCheckTask {
    @Value("${tencent.cloud.appId}")
    private String appId;

    @Value("${tencent.cloud.secretId}")
    private String secretId;

    @Value("${tencent.cloud.secretKey}")
    private String secretKey;

    @Value("${tencent.cloud.bucket-public}")
    private String bucketPublic;

    @Resource
    private OrderVoiceTextDao orderVoiceTextDao;

    @Resource
    private OrderMonitoringDao orderMonitoringDao;

    @Async
    @Transactional
    public void checkText(long orderId, String content, String uuid) {
        // 1.审核内容，并返回审核结果
        String label = "Normal"; //审核结果
        String suggestion = "Pass"; //后续建议

        // 后续建议 的模板
        Map<String, String> template = Map.of("0", "Pass", "1", "Block", "2", "Review");

        if (StrUtil.isNotBlank(content)) {
            // 创建COS客户端
            COSCredentials cred = new BasicCOSCredentials(secretId, secretKey);
            Region region = new Region("ap-beijing");
            ClientConfig clientConfig = new ClientConfig(region);
            COSClient client = new COSClient(cred, clientConfig);
            // 封装Request
            TextAuditingRequest request = new TextAuditingRequest();
            request.setBucketName(bucketPublic);
            request.getInput().setContent(Base64.encode(content));
            request.getConf().setDetectType("all");
            // 发送请求获取审核结果
            TextAuditingResponse response = client.createAuditingTextJobs(request);
            AuditingJobsDetail detail = response.getJobsDetail();
            String state = detail.getState();
            List<String> keywords = new ArrayList<>();
            if ("Success".equals(state)) {
                label = detail.getLabel(); //检测结果
                String result = detail.getResult(); //后续建议
                suggestion = template.get(result);
                List<SectionInfo> list = detail.getSectionList();   //违规关键词

                for (SectionInfo info : list) {
                    String keywords1 = info.getPornInfo().getKeywords(); //色情
                    String keywords2 = info.getIllegalInfo().getKeywords(); //违法
                    String keywords3 = info.getAbuseInfo().getKeywords(); //谩骂
                    if (!keywords1.isEmpty()) {
                        List<String> temp = Arrays.asList(keywords1.split(","));
                        keywords.addAll(temp);
                    }
                    if (!keywords2.isEmpty()) {
                        List<String> temp = Arrays.asList(keywords2.split(","));
                        keywords.addAll(temp);
                    }
                    if (!keywords3.isEmpty()) {
                        List<String> temp = Arrays.asList(keywords3.split(","));
                        keywords.addAll(temp);
                    }
                }
            }

            // 2.根据uuid查询id
            Long id = orderVoiceTextDao.searchIdByUuid(uuid);
            if (id == null) {
                throw new ZxdsException("没有找到代驾语音文本记录");
            }

            // 3.将审核结果更新到order_voice_text表中
            Map<String, Object> param = new HashMap<>();
            param.put("id", id);
            param.put("label", label);
            param.put("suggestion", suggestion);
            param.put("keywords", ArrayUtil.join(keywords.toArray(), ","));
            
            int rows = orderVoiceTextDao.updateCheckResult(param);
            if (rows != 1) {
                throw new ZxdsException("更新内容检查结果失败");
            }
            log.debug("更新内容验证成功");

            // 4.查询该订单有多少个录音文本和需要人工审核的文本
            Map<String, Object> map = orderMonitoringDao.searchOrderRecordsAndReviews(orderId);

            id = MapUtil.getLong(map, "id");
            Integer records = MapUtil.getInt(map, "records");
            Integer reviews = MapUtil.getInt(map, "reviews");
            OrderMonitoringEntity entity = new OrderMonitoringEntity();
            entity.setId(id);
            entity.setOrderId(orderId);
            entity.setRecords(records + 1);
            if (suggestion.equals("Review")) {
                entity.setReviews(reviews + 1);
            }
            if (suggestion.equals("Block")) {
                entity.setSafety("danger");
            }

            // 5.更新order_monitoring表中的记录
            orderMonitoringDao.updateOrderMonitoring(entity);
        }
    }
}
```

```java
package com.example.zxds.nebula.service.impl;

import cn.hutool.core.bean.BeanUtil;
import com.example.zxds.nebula.controller.dto.InsertOrderGpsDTO;
import com.example.zxds.nebula.db.dao.OrderGpsDao;
import com.example.zxds.nebula.db.pojo.OrderGpsEntity;
import com.example.zxds.nebula.service.OrderGpsService;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;

import java.util.List;

@Service
@Slf4j
@RequiredArgsConstructor
public class OrderGpsServiceImpl implements OrderGpsService {

    private final OrderGpsDao orderGpsDao;

    // InsertOrderGpsDTO 中的每个属性都会经过校验框架进行校验。
    @Override
    public int insertOrderGps(List<InsertOrderGpsDTO> list) {
        int rows = 0;
        // 遍历参数list集合，取出每个元素，将 InsertOrderGpsDTO 转换成 OrderGpsEntity对象。
        for (InsertOrderGpsDTO dto : list) {
            OrderGpsEntity orderGpsEntity = BeanUtil.copyProperties(dto, OrderGpsEntity.class);
            rows += orderGpsDao.insert(orderGpsEntity);
        }
        return rows;
    }
}
```

```javascript
//GPS定位变化就自动提交给后端
uni.onLocationChange(function(resp) {
    ……

    let baseUrl = 'http://192.168.99.106:8201/zxds-driver';
    if (workStatus == '开始接单') {
        ……
    } else if (workStatus == '开始代驾') {
        let executeOrder = uni.getStorageSync('executeOrder');
        if (executeOrder != null) {
            gps.push({
                orderId: executeOrder.id,
                customerId: executeOrder.customerId,
                latitude: latitude,
                longitude: longitude,
                speed: speed
            });

            //把GPS定位保存到HBase中，每凑够20个定位就上传一次，减少服务器的压力
            if (gps.length == 20) {
                uni.request({
                    url: `${baseUrl}/order/gps/insertOrderGps`,
                    method: 'POST',
                    header: {
                        token: uni.getStorageSync('token')
                    },
                    data: {
                        list: gps
                    },
                    success: function(resp) {
                        if (resp.statusCode == 401) {
                            uni.redirectTo({
                                url: '/pages/login/login'
                            });
                        } else if (resp.statusCode == 200 && resp.data.code == 200) {
                            let data = resp.data;
                            console.log("上传GPS成功");
                        } else {
                            console.error('保存GPS定位失败', resp.data);
                        }
                        gps.length = 0;
                    },
                    fail: function(error) {
                        console.error('保存GPS定位失败', error);
                    }
                });
            }
        }
    }
```

```java
    public PageUtils searchOrderByPage(SearchOrderByPageForm form) {
```

```javascript
async loadDataList() {
    let that = this;
    that.dataListLoading = true;

    let data = {
        pageIndex: that.pageIndex,
        pageSize: that.pageSize,
        orderId: that.dataForm.orderId == '' ? null : that.dataForm.orderId,
        driverId: that.dataForm.driverId == '' ? null : that.dataForm.driverId,
        customerId: that.dataForm.customerId == '' ? null : that.dataForm.customerId,
        status: that.dataForm.status == '' ? null : that.dataForm.status
    };
    if (that.dataForm.date != null && that.dataForm.date.length == 2) {
        let startDate = that.dataForm.date[0];
        let endDate = that.dataForm.date[1];
        data.startDate = dayjs(startDate).format('YYYY-MM-DD');
        data.endDate = dayjs(endDate).format('YYYY-MM-DD');
    }

  let resp = await axios.post(`${that.$baseUrl}order/searchOrderByPage`, data, {
    headers : {
      token: localStorage.getItem("token")
    }

  });
  
  let result = resp.data.result;
  let list = result.list;
      
  for (let one of list) {
      one.status = status[one.status + ''];
      if (!one.hasOwnProperty('realMileage')) {
          one.realMileage = '--';
      }
      
      if (!one.hasOwnProperty('realFee')) {
          one.realFee = '--';
      }
  }
  that.dataList = list;
  that.totalCount = Number(result.totalCount);
  that.dataListLoading = false;
},
```

```java
private final NebulaServiceApi nebulaServiceApi;

// 查询订单 全面的/综合性的 信息。
@Override
public Map<String, Object> searchOrderComprehensiveInfo(long orderId) {

    Map<String, Object> map = new HashMap<>();

    //查询订单内容信息
    SearchOrderContentForm form1 = new SearchOrderContentForm();
    form1.setOrderId(orderId);
    R r = odrServiceApi.searchOrderContent(form1);
    if (!r.containsKey("result")) {
        throw new ZxdsException("不存在订单记录");
    }
    Map<String,Object> content = (Map<String, Object>) r.get("result");
    map.put("content", content);

    //查询客户信息
    long customerId = MapUtil.getLong(content, "customerId");
    SearchCustomerBriefInfoForm form2 = new SearchCustomerBriefInfoForm();
    form2.setCustomerId(customerId);
    r = cstServiceApi.searchCustomerBriefInfo(form2);
    Map<String, Object> customerInfo = (Map<String, Object>) r.get("result");
    map.put("customerInfo", customerInfo);

    //查询司机信息
    if(content.containsKey("driverId")) {
        long driverId = MapUtil.getLong(content, "driverId");
        SearchDriverBriefInfoForm form3 = new SearchDriverBriefInfoForm();
        form3.setDriverId(driverId);
        r = drServiceApi.searchDriverBriefInfo(form3);
        Map<String, Object> driverInfo = (Map<String, Object>) r.get("result");
        map.put("driverInfo", driverInfo);
    }

    //查询消费规则
    if (content.containsKey("chargeRuleId")) {
        long chargeRuleId = MapUtil.getLong(content, "chargeRuleId");
        SearchChargeRuleByIdForm form4 = new SearchChargeRuleByIdForm();
        form4.setRuleId(chargeRuleId);
        r = ruleServiceApi.searchChargeRuleById(form4);
        Map<String, Object> chargeRule = (Map<String, Object>) r.get("result");
        map.put("chargeRule", chargeRule);
    }

    //查询取消规则
    if (content.containsKey("cancelRuleId")) {
        long cancelRuleId = MapUtil.getLong(content, "cancelRuleId");
        SearchCancelRuleByIdForm form_5 = new SearchCancelRuleByIdForm();
        form_5.setRuleId(cancelRuleId);
        r = ruleServiceApi.searchCancelRuleById(form_5);
        Map<String, Object> cancelRule = (Map<String, Object>) r.get("result");
        map.put("cancelRule", cancelRule);
    }

    //查询分账规则
    if (content.containsKey("profitSharingRuleId")) {
        long profitSharingRuleId = MapUtil.getLong(content, "profitSharingRuleId");
        SearchProfitSharingRuleByIdForm form6 = new SearchProfitSharingRuleByIdForm();
        form6.setRuleId(profitSharingRuleId);
        r = ruleServiceApi.searchProfitSharingRuleById(form6);
        Map<String, Object> profitSharingRule = (Map<String, Object>) r.get("result");
        map.put("profitSharingRule", profitSharingRule);
    }


    //查询GPS规划线路
    CalculateDriveLineForm form7 = new CalculateDriveLineForm();
    Map<String, Object> startPlaceLocation = (Map<String, Object>) content.get("startPlaceLocation");
    Map<String, Object> endPlaceLocation = (Map<String, Object>) content.get("endPlaceLocation");
    form7.setStartPlaceLatitude(MapUtil.getStr(startPlaceLocation, "latitude"));
    form7.setStartPlaceLongitude(MapUtil.getStr(startPlaceLocation, "longitude"));
    form7.setEndPlaceLatitude(MapUtil.getStr(endPlaceLocation, "latitude"));
    form7.setEndPlaceLongitude(MapUtil.getStr(endPlaceLocation, "longitude"));
    r = mpsServiceApi.calculateDriveLine(form7);
    Map<String, Object> driveLine = (Map<String, Object>) r.get("result");
    map.put("driveLine", driveLine);

    int status = MapUtil.getInt(content, "status");
    if (status >= 5 && status <= 8) {
        //查询订单GPS定位记录
        SearchOrderGpsForm form_8 = new SearchOrderGpsForm();
        form_8.setOrderId(orderId);
        r = nebulaServiceApi.searchOrderGps(form_8);
        List<Map<String, Object>> orderGps = (List<Map<String, Object>>) r.get("result");
        map.put("orderGps", orderGps);
    } else if (status == 4) {
        //查询订单中最后的GPS定位
        SearchOrderLastGpsForm form9 = new SearchOrderLastGpsForm();
        form9.setOrderId(orderId);
        r = nebulaServiceApi.searchOrderLastGps(form9);
        Map<String, Object> lastGps = (Map<String, Object>) r.get("result");
        map.put("lastGps", lastGps);
    }
    return map;
}
```

# Prometheus&Grafana&SkyWalking

## 可观测性三件套

**Prometheus**

- **就像一个自动抄表员，每隔几秒就去你的应用门口看一眼，记录下'请求数、错误率、响应时间'等各种指标数据，存进自己的数据库里，让你随时能查。**
- **完全和语言无关，适用于任何语言**：Java、Go、Python、Node.js、Ruby、PHP、.NET，甚至Shell脚本

**Grafana**

- **就像一个数据画师，能把Prometheus记录的那些枯燥数字，变成漂亮的图表和仪表盘，让你一眼就看清系统的运行状态。**
- **完全和语言无关，它只是一个图表展示工具，不管数据从哪来。**

**SkyWalking**

- **就像一个侦探，能追踪每个请求的完整旅程，告诉你这个请求经过了哪些服务、每个环节花了多长时间、到底慢在哪里。**
- **支持多种语言，Java 语言支持最完善，也支持：Go、Python、Node.js、PHP 等。**

**一句话总结：**

**"Prometheus告诉你'出问题了'，Grafana让你'看清楚问题'，SkyWalking告诉你'问题在哪'。三个一起用，系统出了问题无处可逃！"**

## 开发阶段可以用监控

**1. 找慢接口（SkyWalking）**

- 你写完一个接口，点一下页面，SkyWalking直接告诉你：这个请求总共500ms，其中MySQL查询占了400ms。
- **发现问题**：哦，原来是SQL没加索引。马上优化，不用等到上线后被用户骂。

**2. 看内存泄漏苗头（Prometheus）**

- 本地压测跑半小时，Prometheus画的JVM堆内存曲线一直往上走、不回落。
- **发现问题**：某个Map只增不减，赶紧查代码。现在修改成本最低。

**3. 验证依赖是否健康**

- 你的订单服务调用了用户服务，在开发环境偶尔超时。
- **发现问题**：可能是网络或配置问题，提前调好，避免上线后连锁故障。

## 生产环境也可以用监控

**1. 24小时盯梢（告警）**

- Prometheus配规则：QPS突降 -> 可能服务挂了 -> 电话告警
- 响应时间突增 -> 可能DB有问题 -> 微信通知

**2. 故障定位（SkyWalking）**

用户反馈“下单慢”，不用猜是哪个服务。打开SkyWalking看链路：

- 网关(10ms) → 订单服务(5s) → 库存服务(超时)
- 一秒定位：哦，库存服务连Redis连不上了。

**3. 容量规划（Prometheus + Grafana）**

- 看过去一周的QPS趋势，预测下个月要不要扩容
- 看CPU、内存水位，决定什么时候加机器

## Spring Boot Actuator

### Spring Boot Actuator 概述

`**Actuator**`**是 SpringBoot 官方自带的模块。****Actuator 启用之后，自动对外暴露了很多接口，让应用能报告自己的各种指标数据，供Prometheus这样的监控系统采集。**

```java
// 不加Actuator时
@RestController
public class MyController {
    @GetMapping("/hello")
    public String hello() {
        return "Hello";
    }
    // 只有业务接口，没有监控数据
}

// 加了Actuator后
// 自动多了这些接口：
// GET /actuator/health  → {"status":"UP"}
// GET /actuator/metrics → 各种指标数据
// GET /actuator/info    → 应用信息
// GET /actuator/prometheus → Prometheus格式的指标
```

## SkyWalking

### SkyWalking 主要作用

**它是专门为分布式系统（比如微服务架构）设计的**应用性能监控**（APM）和**分布式追踪**工具，主要解决“一个请求经过多个服务，出问题或变慢时难以排查”的痛点。**

具体来说，它的核心价值体现在三个方面：

1. **分布式追踪**：记录一个请求从开始到结束，在各个服务之间（如A调用B，B调用C）以及服务内部（如数据库查询、Redis缓存）的完整调用链路和耗时。你可以通过它清晰地看到请求的“全程路线图”。
2. **性能指标分析**：监控各个服务的实时负载（每分钟调用量）、成功率、平均延迟等关键指标，帮你快速发现性能瓶颈或异常波动。
3. **服务拓扑图**：自动生成服务之间的调用关系图，让你一眼看清整个系统的依赖关系、流量走向以及每个节点的健康状况。

总的来说，SkyWalking就像是分布式系统的“行车记录仪”和“体检中心”，让你在复杂的微服务环境中，能够快速定位故障和理解性能。

### JVM 内存监控图

![198f3018-4b66-46c8-b159-d9e4bbbd79a0.png](images/JRFWbXjTIokTdbx9PXOcSipenjg.png)

**四条线的含义**

| **线条** | **全称** | **含义** | **正常什么样** |
| --- | --- | --- | --- |
| **heap** | 堆内存已用量 | 你创建的对象（如`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">new Order()</font>`）占用的内存 | 波浪形，用完就GC回收 |
| **heap_max** | 堆内存最大值 | JVM最多能用的堆内存（-Xmx配置） | 平稳的水平线 |
| **noheap** | 非堆内存已用量 | 方法区、常量池、类元数据等 | 相对平稳 |
| **noheap_max** | 非堆内存最大值 | 非堆内存上限 | 平稳的水平线 |

**程序员怎么看这张图？**

**正常情况**

- **heap** 曲线像锯齿波浪：上升（创建对象）→ 下降（GC回收）→ 再上升
- **heap** 从未接近 **heap_max**（有足够余量）

**异常情况**

| **现象** | **可能问题** |
| --- | --- |
| **heap** 持续上升不下降 | 内存泄漏（对象无法回收） |
| **heap** 频繁触顶 **heap_max** | 内存不够用，要调大-Xmx |
| **heap** 曲线太平 | 可能没流量或代码有问题 |

**日常看 heap 曲线是不是锯齿状就行，其他不用管。**

### **JVM GC Time (ms)**

![3d5a3e55-a522-465f-a49d-83d76c2a1177.png](images/QXe3b5BuhojdmNxRQ8qcIjIAnQy.png)

**三条线分别代表什么**

| **线条** | **全称** | **含义** |
| --- | --- | --- |
| **young_gc** | 年轻代GC（Minor GC） | 回收"朝生夕死"的对象（最频繁） |
| **old_gc** | 老年代GC（Full GC） | 回收长期存活的对象（较少发生） |
| **normal_gc** | 普通GC | 通常指young_gc或其他混合GC |

**Y轴（0-25ms）代表什么：每次GC操作花了多少毫秒**。数值越小越好。

**健康状态**

- **所有线条都趴在0-5ms之间** → GC很快，几乎不影响业务
- **young_gc有轻微波动** → 正常，说明有新对象不断创建和回收

**不健康状态**

| **现象** | **说明** |
| --- | --- |
| **线条飙到25ms以上** | GC时间太长，请求可能会卡顿 |
| **old_gc突然出现且很高** | 老年代GC很耗时，可能内存快满了 |
| **线条持续在高位** | 系统可能快不行了 |

### JVM GC Count

![c6a65f47-848d-4e3e-9dec-ca5e76929403.png](images/IvF4bfcbWopgkExgBTbczCpXnoh.png)

**怎么看**

- **Y轴（0-1）**：每分钟GC发生了多少次
- **三条线**：不同类型的GC（young_gc/old_gc/normal_gc）

**正常 vs 异常**

| **状态** | **说明** |
| --- | --- |
| **正常** | 0-几次/分钟，平稳 |
| **异常** | 几十次/分钟，说明对象创建太多或内存太小 |

### **JVM Thread Count**

查看项目跑了多少个线程

![394f4394-3584-42c4-92e5-07b504ab2e78.png](images/YQ38bNGMlojLgTxQpqZce9EOngh.png)

**三条线分别代表什么**

| **线条** | **含义** | **简单理解** |
| --- | --- | --- |
| **live** | 当前存活的线程数 | 现在有多少线程在工作 |
| **daemon** | 后台守护线程数 | 后台默默干活的（如GC线程） |
| **peak** | 历史峰值线程数 | 最多时达到多少 |

**正常 vs 异常**

| **状态** | **说明** |
| --- | --- |
| **正常** | 线条平稳，live < peak（有冗余容量） |
| **异常** | live 持续接近 peak 且上升 → 线程泄露或并发太高 |

### 接口 QPS 监控

查看每个接口的每秒请求数（QPS），找出流量最高的接口

```plaintext
sum by (uri) (rate(http_server_requests_seconds_count[1m]))
```

- **计算逻辑**：统计过去1分钟内，**每个接口(uri)每秒接收的请求数(QPS)**
- `<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">rate</font>`：计算每秒增长率
- `<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">sum by (uri)</font>`：按接口地址分组求和

![26efa3c6-8f32-49ae-baf8-d44c27de0942.png](images/WykcboqlSoBtvUxkPsGco4TOnkg.png)

| **uri** | **值** | **含义** |
| --- | --- | --- |
| `<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">/actuator/prometheus</font>` | **0.2 QPS** | 过去1分钟平均每秒有0.2个请求（即约12个/分钟） |
| `<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">/order/createNewOrder</font>` | **0 QPS** | 过去1分钟内**没有收到任何请求** |

### 接口 95 分位延迟

需要在 `application.yml`中添加如下的配置，**这个配置告诉Spring Boot：为每一个HTTP请求，按响应时间分桶（分桶就是分组）统计（比如记录有多少请求在0-10ms、10-100ms、100-500ms等区间），这样Prometheus才能用这些桶数据计算出P95、P99等百分位响应时间。**

```yaml
management:
  metrics:
    distribution:
      percentiles-histogram:
        http.server.requests: true
```

执行这个 QL：

```plaintext
histogram_quantile(0.95, sum by (le, uri) (rate(http_server_requests_seconds_bucket[1m])))
```

**基于过去 1 分钟内，每个接口（uri）的耗时桶数据，计算出 95% 的请求都在多少秒内完成。**

**假如我要求某个请求的 95%的请求量都要在 2 秒之内响应完毕，这个数据就能帮上忙。**

### 接口错误率

```plaintext
sum(rate(http_server_requests_seconds_count{status=~"5.."}[1m])) / sum(rate(http_server_requests_seconds_count[1m])) * 100
```

计算5xx错误的百分比，大于0说明有异常。

```plaintext
sum(rate(http_server_requests_seconds_count{status="5.."}[1m]))  # 5xx错误请求数/秒
/
sum(rate(http_server_requests_seconds_count[1m]))               # 总请求数/秒
* 100                                                            # 转成百分比
```

### JVM 堆内存使用

```plaintext
sum by (id) (jvm_memory_used_bytes{area="heap"})
```

**例如执行结果：****如果Old Gen持续上涨且GC后不降，就是不好；如果Eden和Survivor有涨有落、Old Gen稳定，就是好。**

![71597575-34c2-4ee3-94f0-ac9be4320186.png](images/KmuLbqCPRoQnfIxMQNCcmQFAnph.png)

| **JVM 堆内存的三个区域** | **含义** |
| --- | --- |
| **Eden Space（伊甸园区）属于年轻代** | 新创建的对象都在这里，满了会触发**Minor GC（频率高，速度快，无感知）** |
| **Survivor Space（幸存者区）属于年轻代** | Minor GC后存活的对象移到这里（第一次 GC 后的对象还活着的到这里） |
| **Old Gen（老年代）** | 多次 GC 后，长期存活的对象移到这里，这里**满了**会触发 **Full GC（频繁Full GC是**大问题**，相当于系统在**生死边缘挣扎**）** |

**为啥这么分？**

因为大多数对象**朝生夕死**（比如一次HTTP请求创建的对象，用完就扔），所以：

- 把**短命对象**放一起（年轻代），集中快速回收
- **长寿对象**挪到一边（老年代），避免反复扫描

### GC 暂停时间

```plaintext
rate(jvm_gc_pause_seconds_sum[1m])
```

查看每秒**GC暂停时间**（**GC 暂停时间指的是 GC 努力工作的时间**），值越大说明GC越频繁/越久

```plaintext
查询：sum by (uri) (rate(http_server_requests_seconds_count[1m]))
可视化：Bar gauge 或 Table
标题：接口QPS排行榜
单位：rps
说明：找出流量最高的接口
```

### Panel 2：接口95分位延迟

```plaintext
查询：histogram_quantile(0.95, sum by (le, uri) (rate(http_server_requests_seconds_bucket[1m])))
可视化：Gauge 或 Stat
标题：接口P95延迟
单位：seconds
阈值：2 （超过2秒变红）
说明：监控SLA达标情况
```

### Panel 3：接口错误率

```plaintext
查询：sum(rate(http_server_requests_seconds_count{status=~"5.."}[1m])) / sum(rate(http_server_requests_seconds_count[1m])) * 100
可视化：Gauge
标题：接口错误率
单位：percent
阈值：1 （超过1%变黄），5（超过5%变红）
说明：5xx错误占比
```

### Panel 4：JVM堆内存

```plaintext
查询：sum by (id) (jvm_memory_used_bytes{area="heap"})
可视化：Time series（折线图）
标题：JVM堆内存使用
单位：bytes
说明：监控内存泄漏
```

### Panel 5：GC暂停时间

```plaintext
查询：rate(jvm_gc_pause_seconds_sum[1m])
可视化：Time series
标题：GC暂停时间
单位：seconds
说明：GC压力监控
```

### 小技巧

1. **固定时间范围****：右上角选"Last 15 minutes"或"Last 1 hour"**
2. **自动刷新****：右上角选"5s"或"10s"，数据实时更新**
