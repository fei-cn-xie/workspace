# 司机抢单（秒杀超卖）

超卖问题我们在之前的项目中就遇到过。主要的原因是：读取库存和扣减库存不是原子性操作导致的。如果使用传统数据库的话，一般可以使用乐观锁机制防止超卖。但传统数据库的性能较差，一般会选择 redis 乐观锁+redis 事务来解决这个问题。

这里我们使用一种更加现代化的、安全的、效率高的方式来防止超卖的发生（**司机抢单也属于超卖问题：一个订单只能被一个司机抢到**）：**Lua 脚本**。

## Lua 脚本概述

Lua是一种**轻量级、可嵌入的脚本语言**，主要用于**应用程序的扩展和配置**。

主要作用：**嵌入到其他程序中（比如游戏、工业软件）**，让开发者能**在不修改主程序的情况下定制逻辑和行为**

Redis Lua是一种**专为Redis设计的受限Lua方言**，主要用于在Redis服务器端执行原子操作，不能作为通用Lua脚本使用。

**Redis Lua脚本是一种让用户能在Redis服务器内部，以原子方式、高性能地执行复杂数据操作的扩展机制。**

### **它是干什么的？**

它允许你将多个Redis命令**组合成一个脚本**，发送到Redis服务器**一次性执行**。脚本就像是一个自定义的、功能更强的Redis命令。

**简单示例：** 实现一个“如果键不存在则设置，并设置过期时间”的复合操作。

```lua
-- 这是一个原子操作：检查、设置、设置过期时间，中间不会被其他客户端打断
if redis.call("EXISTS", KEYS[1]) == 0 then
    redis.call("SET", KEYS[1], ARGV[1])
    redis.call("EXPIRE", KEYS[1], ARGV[2])
    return 1 -- 表示设置成功
else
    return 0 -- 表示键已存在
end
```

`<font style="color:#000000;">ARGV[1]</font>`是传递给 Lua 脚本的第一个参数。`<font style="color:#000000;">ARGV[2]</font>`则是第二个参数。

### **存在的核心意义（解决了什么问题）**

| 问题 | 传统方式（多命令） | 使用Lua脚本 |
| --- | --- | --- |
| **原子性** | 多个命令可能被其他客户端插队，需要`<font style="color:#000000;">WATCH</font>`+事务，复杂且可能失败。 | **天生原子**：脚本执行期间，Redis不会执行其他命令。 |
| **减少网络开销** | 每个命令一次网络往返（RTT），N个命令就是N次RTT，延迟高。 | **一次网络往返**：整个脚本一次发送，一次返回结果。 |
| **减少数据序列化** | 客户端需要接收**中间结果**，进行**多次序列化**处理。 | **服务器内部处理**：中间数据在Lua变量中流转，无需网络传输和客户端序列化。 |
| **实现复杂逻辑** | 无法在 Redis 服务器内部做条件判断、循环、计算等。 | **可编程**：具备变量、条件、循环、数学计算等完整的编程能力。 |
| **避免竞争条件** | 实现“检查-设置”这类模式非常困难，易出错。 | **简单可靠**：完美解决竞争条件。 |

### **核心特性总结**

1. **原子性**：最重要的特性，整个脚本在执行时是独占的。
2. **高性能**：网络和序列化开销极小。

**因此，Redis Lua脚本存在的根本意义在于：它把Redis从一个简单的“命令执行者”升级为了一个“逻辑处理器”，使开发者能在保证原子性和高性能的前提下，实现复杂的业务逻辑和数据操作。** 常见应用场景包括：分布式锁、限流器、库存扣减、原子性的统计计算等。

## 司机抢单实现原理

1. Redis Lua 脚本在其中起到最核心的作用。
2. 它的表现就是一个**分布式锁**的表现。
3. Redis Lua 脚本是一个**不可分割的 Redis 命令**，执行过程中其他 Redis 命令是无法执行的。因为 Redis 核心是单线程。
4. 即使在并发的环境下，Redis 命令也是排队执行的。
5. 我们在 Redis Lua 脚本中编写业务逻辑代码，自然这个**业务逻辑执行过程**不是并发的（**只有这一个业务在执行**）。
  1. 业务第一步（读 get）：通过 key（order#123）获取 value，看看 value 是不是 none
  2. 业务第二步（写 set）：如果不是 none，代表这个单子已经被其他司机拿走了。如果是 none 就把 none 修改为抢单司机的 id，代表被这个司机抢走了。
  3. 读写是一个整体，等于不存在并发的问题。
6. 单线程效率不会很差吗？不会，Lua 脚本属于 Redis 内部命令执行，无网络开销，性能极高。
7. Redis Lua 脚本执行结束之后返回一个字符串结果，后续程序通过这个字符串结果继续执行，如果 Lua 脚本返回 SUCCESS，则表示当前司机抢单成功，去修改 mysql 数据库表。
8. mysql 数据库表修改成功后，删除 Redis 中的订单缓存。

**以上原理，等于我们使用 Redis Lua 脚本实现了一个分布式锁。**

## Redis 持久化策略的配置

对于代驾系统来说，redis 中存储的要抢单的 key 比较重要，如果 key 丢失，则表示订单在逻辑上是消失的，没有司机再能抢到这个订单了。因此 Redis 的持久化策略就比较重要了。以防 redis 崩溃后数据丢失。

我们采用 AOF 和 RDB 混合持久化方式，在原配置文件中添加以下配置：

```nginx
appendonly yes                                # 开启AOF持久化模式
appendfilename "appendonly.aof"               # aof文件名
appendfsync everysec                          # 每秒同步一次到磁盘，平衡性能和数据安全
aof-use-rdb-preamble yes                      # 启用混合持久化
```

另外关闭单独的 RDB 持久化模式：

```nginx
save ""                                       # 彻底关闭RDB

#注释掉
#save 900 1
#save 300 10
#save 60 10000
```

**先来看看 Redis Lua 脚本怎么写：**

```lua
-- 抢单脚本
-- KEYS[1]: 订单键，如 "order#123"
-- ARGV[1]: 司机ID，如 "1001"
-- 返回值:
--   "KEY_NOT_EXIST" - 订单不存在
--   "ALREADY_TAKEN:司机ID" - 订单已被抢
--   "SUCCESS" - 抢单成功

local key = KEYS[1]
local driver = ARGV[1]

local current = redis.call('GET', key)
if current == false then
    return 'KEY_NOT_EXIST'
end

if current ~= 'none' then
    return 'ALREADY_TAKEN:' .. current
end

redis.call('SET', key, driver)
redis.call('EXPIRE', key, 300)

return 'SUCCESS'
```

在`<font style="color:#000000;background-color:rgba(220, 240, 255, 0.3) !important;">com.example.zxds.odr.service.impl</font>`包`<font style="color:#000000;background-color:rgba(220, 240, 255, 0.3) !important;">OrderServiceImpl.java</font>`类中，实现抽象方法

```java
// 司机抢单的Redis Lua脚本
private static final String GRAB_ORDER_SCRIPT = """
        local key = KEYS[1]
        local driver = ARGV[1]
        
        local current = redis.call('GET', key)
        if current == false then
            return 'KEY_NOT_EXIST'
        end
        
        if current ~= 'none' then
            return 'ALREADY_TAKEN:' .. current
        end
        
        redis.call('SET', key, driver)
        redis.call('EXPIRE', key, 300)
        
        return 'SUCCESS'
        """;

private DefaultRedisScript<String> grabScript;

@PostConstruct
public void init() {
    grabScript = new DefaultRedisScript<>();
    grabScript.setScriptText(GRAB_ORDER_SCRIPT);
    grabScript.setResultType(String.class);
}

@Override
@Transactional
public String acceptNewOrder(long driverId, long orderId) {

    String key = "order#" + orderId;
    String driverIdStr = String.valueOf(driverId);

    // 执行Redis Lua脚本进行抢单
    String result = stringRedisTemplate.execute(grabScript, Collections.singletonList(key), driverIdStr);
    if ("KEY_NOT_EXIST".equals(result)) {
        return "抢单失败：订单不存在";
    }
    if (result.startsWith("ALREADY_TAKEN:")) {
        String takenDriverId = result.substring(14);
        return "抢单失败：订单已被司机" + takenDriverId + "抢走";
    }
    if (!"SUCCESS".equals(result)) {
        return "抢单失败";
    }

    // 抢单成功，更新mysql
    try {
        Map<String, Object> params = new HashMap<>();
        params.put("driverId", driverId);
        params.put("orderId", orderId);
        int rows = orderDao.acceptNewOrder(params);
        if (rows == 1) {
            // 删除redis中的订单缓存
            stringRedisTemplate.delete(key);
            return "抢单成功";
        }else{
            // 将redis的订单缓存的value重新修改为none
            stringRedisTemplate.opsForValue().set(key, "none", 15, TimeUnit.MINUTES);
            return "抢单失败";
        }
    } catch (Exception e) {
        // 将redis的订单缓存的value重新修改为none
        stringRedisTemplate.opsForValue().set(key, "none", 15, TimeUnit.MINUTES);
        throw new ZxdsException(e.getMessage());
    }
}
```

```javascript
    if (ref.settings.autoAccept) {
```

```java
@Override
public Integer searchOrderStatus(Map<String,Object> param) {
    Integer status = orderDao.searchOrderStatus(param);
    if (status == null) {
        throw new ZxdsException("没有查询到数据，请核对查询条件");
    }
    return status;
}


@Override
@Transactional
public String deleteUnAcceptOrder(Map<String, Object> param) {
    long orderId = MapUtil.getLong(param, "orderId");
    String orderKey = "order#" + orderId;

    // 定义Lua脚本：原子性删除未接单的订单
    String luaScript = """
    local orderKey = KEYS[1]
    local exists = redis.call('EXISTS', orderKey)
    if exists == 0 then
        return 'KEY_NOT_EXIST'
    end
    local current = redis.call('GET', orderKey)
    if current ~= 'none' then
        return 'CANNOT_CANCEL:ALREADY_TAKEN:' .. current
    end
    redis.call('DEL', orderKey)
    return 'SUCCESS'
    """;

    DefaultRedisScript<String> script = new DefaultRedisScript<>();
    script.setScriptText(luaScript);
    script.setResultType(String.class);

    // 执行Lua脚本
    String result = stringRedisTemplate.execute(
            script,
            Collections.singletonList(orderKey)
    );

    // 处理脚本执行结果
    if ("KEY_NOT_EXIST".equals(result)) {
        return "订单取消失败：订单不存在或已过期";
    }

    if (result.startsWith("CANNOT_CANCEL:ALREADY_TAKEN:")) {
        String driverId = result.substring(28); // 从第28个字符开始是司机ID
        return "订单取消失败：订单已被司机" + driverId + "接单，无法取消";
    }

    if (!"SUCCESS".equals(result)) {
        return "订单取消失败：系统异常";
    }

    // Redis删除成功，更新MySQL数据库
    int rows = orderDao.deleteUnAcceptOrder(param);
    if (rows != 1) {
        // 如果MySQL删除失败，需要恢复Redis状态
        stringRedisTemplate.opsForValue().set(orderKey, "none", 16, TimeUnit.MINUTES);
        return "订单取消失败：数据库操作失败";
    }

    return "订单取消成功";
}
```

因为乘客端的等待司机接单的倒计时为15分钟，现在后端Redis里面的抢单缓存也是15分钟。如果移动端倒计时到15分钟恰好结束，这时候发起Ajax请求取消订单，那么就会给后端程序带来困难，因为在Redis里面已经不存在抢单缓存了，后端程序无法判断到底是司机抢单成功后删除了抢单缓存，还是因为没有司机抢单，缓存过期自动删除了。所以我们把Redis抢单缓存延长到16分钟。把 `<font style="color:#000000;">com.example.zxds.odr.service.impl.OrderServiceImpl</font>` 类中的 `<font style="color:#000000;">15</font>`全部修改为 `<font style="color:#000000;">16</font>`。

# 抢单缓存超期需自动删除订单和账单

乘客端正常来说，创建代驾订单，进入倒计时，取消订单有两个途径：

1. 倒计时结束了，当前系统会自动发送 ajax 请求取消订单。
2. 或者乘客在倒计时没有结束之前，手动点击取消订单，发送 ajax 请求取消订单。

大家思考一个问题：对于非正常情况会怎样呢？例如乘客创建订单之后进入了倒计时。突然微信闪退了。然后很长一段时间都没有再登录微信小程序，16 分钟都已经过去了，订单缓存已经过期了。会怎样？？？乘客重新登录小程序，因为数据库中存在没有接单的订单，小程序会跳转到`<font style="color:#000000;background-color:rgba(220, 240, 255, 0.3) !important;">create_order.vue</font>`页面，继续开始倒计时等待司机接单。（**当然，这个功能还没有实现**）

由于抢单缓存早就销毁了，即便倒计时结束，发起Ajax请求去关闭订单。但是业务层发现没有抢单缓存，系统会认为有司机接单了，实际上根本没有司机接单，另外关闭订单的前提是存在订单缓存才能关，因此订单也无法关闭，于是就僵持在这里了。

为了避免上面情况的发生，我们用Java程序监听抢单缓存的销毁事件，一旦监听到抢单缓存销毁了，就需要把关联的订单和账单记录给删除掉。上面的问题就不存在了。

## 编写代码监听 redis key 的过期

以下是 Redis 中发布/订阅机制。发布者是 Redis 服务器。订阅者是监听器。

我们只需要创建一个频道对象。当某个事件发生之后，发布者会自动通过频道广播消息。所有的订阅者都可以收到。

订阅者收到消息之后可以对业务进行处理。

找到 `<font style="color:#000000;">RedisConfig</font>`配置类，**添加**以下代码：

```java
@Resource
private RedisConnectionFactory redisConnectionFactory;

/**
 * 定义Redis键过期事件的监听频道
 * 格式：__keyevent@<db>__:<event>
 * @5: 只监听5号数据库，实现业务隔离
 * expired: 监听键过期事件
 * Redis会在键过期时自动向此频道发布消息
 * 创建一个频道，如果key过期，redis服务器会作为消息的发布者，通过这个频道发布消息。那么如果有订阅者（监听器），这些订阅者就能收到消息。
 */
@Bean
public ChannelTopic expiredTopic() {
    return new ChannelTopic("__keyevent@5__:expired");  
}

/**
 * 创建Redis消息监听容器
 * 负责管理Redis消息监听器：
 * 1. 维护Redis连接
 * 2. 接收指定频道的消息
 * 3. 将消息分发给注册的监听器
 */
@Bean
public RedisMessageListenerContainer redisMessageListenerContainer() {
    RedisMessageListenerContainer redisMessageListenerContainer = new RedisMessageListenerContainer();
    redisMessageListenerContainer.setConnectionFactory(redisConnectionFactory);
    return redisMessageListenerContainer;
}
```

接下来该编写监听器了，监听器会自动注册到上面编写的监听器容器中“RedisMessageListenerContainer”

在`<font style="color:#000000;background-color:rgba(220, 240, 255, 0.3) !important;">com.example.zxds.odr.config</font>`包中创建`<font style="color:#000000;background-color:rgba(220, 240, 255, 0.3) !important;">KeyExpiredListener.java</font>`类

```java
package com.example.zxds.odr.config;

import com.example.zxds.odr.db.dao.OrderBillDao;
import com.example.zxds.odr.db.dao.OrderDao;
import lombok.extern.slf4j.Slf4j;
import org.springframework.data.redis.connection.Message;
import org.springframework.data.redis.listener.KeyExpirationEventMessageListener;
import org.springframework.data.redis.listener.RedisMessageListenerContainer;
import org.springframework.data.redis.serializer.JdkSerializationRedisSerializer;
import org.springframework.stereotype.Component;
import org.springframework.transaction.annotation.Transactional;

import javax.annotation.Resource;
import java.util.Map;

@Slf4j
@Component
public class KeyExpiredListener extends KeyExpirationEventMessageListener {
    @Resource
    private OrderDao orderDao;

    @Resource
    private OrderBillDao orderBillDao;

    // 构造注入。
    public KeyExpiredListener(RedisMessageListenerContainer listenerContainer) {
        super(listenerContainer);
    }

    @Override
    @Transactional
    public void onMessage(Message message, byte[] pattern) {
        // message参数就是Redis服务器通过频道发过来的消息。
        // 判断，如果这个消息是通过这个键过期频道发过来的。
        if (new String(message.getChannel()).equals("__keyevent@5__:expired")) {
            //反序列化Key，否则出现乱码（如果使用的RedisTemplate，则需要编写以下两行代码进行反序列化）
            //JdkSerializationRedisSerializer serializer = new JdkSerializationRedisSerializer();
            //String key = serializer.deserialize(message.getBody()).toString();

            // 如果使用的 StringRedisTemplate，这样写即可
            String key = new String(message.getBody());
            
            // 如果key属于订单缓存
            if (key.contains("order#")) {
                long orderId = Long.parseLong(key.split("#")[1]);
                int rows = orderDao.deleteUnAcceptOrder(Map.of("orderId", orderId));
                if (rows == 1) {
                    log.info("删除了无人接单的订单：" + orderId);
                }
                rows = orderBillDao.deleteUnAcceptOrderBill(orderId);
                if (rows == 1) {
                    log.info("删除了无人接单的账单：" + orderId);
                }
            }
        }
        super.onMessage(message, pattern);
    }
}
```

```javascript
formatPolyline(polyline) {
    let coors = polyline;
    let pl = [];
    //坐标解压（返回的点串坐标，通过前向差分进行压缩）
    const kr = 1000000;
    for (let i = 2; i < coors.length; i++) {
        coors[i] = Number(coors[i - 2]) + Number(coors[i]) / kr;
    }
    //将解压后的坐标放入点串数组pl中
    for (let i = 0; i < coors.length; i += 2) {
        pl.push({
            longitude: coors[i + 1],
            latitude: coors[i]
        });
    }
    return pl;
},
```

```javascript
calculateLine() {
    let that = this;
    //如果还没有获得到司机的定位，就不计算最佳线路
    if (that.latitude == 0 || that.longitude == 0) {
        return;
    }
    qqmapsdk.direction({
        mode: that.mode, 
        from: {
            latitude: that.latitude,
            longitude: that.longitude
        },
        to: {
            latitude: that.targetLatitude,
            longitude: that.targetLongitude
        },
        success: function(resp) {
            let route = resp.result.routes[0];
            let distance = route.distance;
            let duration = route.duration;

            that.distance = Math.ceil((distance / 1000) * 10) / 10;
```

# 乘客端的司乘同显-司机实时上传定位

乘客端的司乘同显要复杂一些。因为它包括两个阶段：

1. 一阶段，司机赶往代驾点的过程：在乘客手机上要能够实时看到司机的位置，此时需要在**乘客端**上可以**实时获取到司机的定位**。
2. 二阶段，司机代驾的过程：乘客端直接使用自己的实时定位即可。

接下来，我们先把一阶段实现一下。思路是：司机端实时将定位上传到 redis 中，乘客端从 redis 中实时获取司机定位信息即可。

```java
@Override
public void updateOrderLocationCache(Map<String, Object> param) {
    long orderId = MapUtil.getLong(param, "orderId");
    String latitude = MapUtil.getStr(param, "latitude");
    String longitude = MapUtil.getStr(param, "longitude");
    String location = latitude + "#" + longitude;
    redisTemplate.opsForValue().set("order_location#" + orderId, location, 10, TimeUnit.MINUTES);
}

@Override

public Map<String, Object> searchOrderLocationCache(long orderId) {
    Object obj = redisTemplate.opsForValue().get("order_location#" + orderId);
    if (obj != null) {
        String[] temp = obj.toString().split("#");
        String latitude = temp[0];
        String longitude = temp[1];
        Map<String, Object> map = Map.of("latitude", latitude, "longitude", longitude);
        return map;
    }
    return null;
}
```

```javascript
    let coors = polyline;

    //坐标解压（返回的点串坐标，通过前向差分进行压缩）
    const kr = 1000000;
    for (let i = 2; i < coors.length; i++) {

    }
```

## 司机到达上车点

司机端工作台页面中有“到达代驾点”的按钮，司机点击按钮之后，发出Ajax请求，把订单的状态改成3。

![f52b41a9-93c9-4151-b188-f0f945cf0952.png](images/TtEVb4mVYohhsExifrOcMwWqnTd.png)

在工作台页面中，“到达代驾点”按钮的标签代码如下

```html
<view class="item" v-show="workStatus == '接客户'" @tap="arriveStartPlaceHandle">
    <image src="../../static/workbench/arrive-start-icon.png" 
           mode="widthFix" 
           class="arrive-start-icon">
    </image>
    <text class="arrive-start-text">到达代驾点</text>
</view>
```

我们实现`<font style="color:#000000;background-color:rgba(220, 240, 255, 0.3) !important;">arriveStartPlaceHandle()</font>`函数的内容，提交Ajax请求

```javascript
arriveStartPlaceHandle() {
    let that = this;
    uni.showModal({
        title: '消息通知',
        content: '确认已经到达了代驾点？',
        success: function(resp) {
            if (resp.confirm) {
                let data = {
                    orderId: that.executeOrder.id,
                    customerId: that.executeOrder.customerId
                };
                that.ajax(that.url.arriveStartPlace, 'POST', data, function(resp) {
                    if (resp.data.rows == 1) {
                        uni.showToast({
                            icon: 'success',
                            title: '订单状态更新成功'
                        });
                        that.workStatus = '到达代驾点';
                        uni.setStorageSync('workStatus', '到达代驾点');
                    }
                });
            }
        }
    });
},
```
