### 早期成果

- **1957年** — Frank Rosenblatt（弗兰克·罗森布拉特） 发明**感知机（Perceptron）**，最早的人工神经网络之一
- **1958年** — McCarthy 发明 **LISP** 编程语言，成为AI研究主要工具
- **1966年** — MIT 开发 **ELIZA**，第一个聊天机器人

→ Mark I 感知机，1958年康奈尔航空实验室

![image.png](images/KSoXbVBB8oJN5qxaDuRc9QeYnqg.png)

Mark I 感知机的核心是模仿生物神经元的处理方式，

通过“**权重 + 求和 + 激活函数**”来进行模式识别与分类。

主要功能：

1. **模式识别（Pattern Recognition）**
可识别简单的几何图案、字母形状等。
2. **自适应学习（Adaptive Learning）**
能通过训练样本调整权值，实现学习与改进。
3. **特征提取（Feature Extraction）**
输入图像通过感知机网络抽取关键特征并参与分类。
4. **多输入并行处理**
输入来自光电传感器阵列（相当于早期摄像机），以并行方式处理。

硬件结构：

- 输入层：64 个光电传感器（模拟“视网膜”）
- 中间层（权重存储）：可调电机控制的电位器
- 输出层：进行线性求和和阈值判断，给出分类结果。

| 对比维度 | Mark I 感知机 | 传统计算机（如当时的 IBM 等） |
| --- | --- | --- |
| 运算模型 | 神经网络模型（权重求和 + 激活） | 冯·诺依曼架构（程序指令控制） |
| 处理方式 | 并行处理输入 | 串行处理指令 |
| 学习能力 | 通过训练样本自动调整权重，实现自适应 | 无自适应能力，必须由程序员编写固定算法 |
| 用途 | 模式识别、图像分类等感知任务 | 数值计算、事务处理 |
| 数据表示 | 权重和阈值、信号强度 | 明确的二进制数据和指令序列 |
| 灵活性 | 可通过学习改变性能 | 性能基于固定程序，不会自我改变 |

## 1970s — 1980s：第一次AI寒冬与知识系统时代

### 第一次AI寒冬（1974-1980）

- 早期研究者**过于乐观的预测**未能实现
- 计算能力严重不足，无法处理复杂问题
- **1969年** — 《Perceptrons》指出单层感知机局限性，**神经网络研究停滞**
- 政府和机构**大幅削减AI研究经费**

### 专家系统的兴起（1980s）

> MYCIN（1972）：诊断血液感染疾病，准确率 **65%**，超过部分非专科医生

MYCIN 的内部结构大致包括：

1. **知识库（Knowledge Base）**：
  - 约 450 条基于领域专家经验的规则，例如：

```plain text
IF 患者的革兰氏染色为阳性
   AND 菌形为球形
THEN 病原体为葡萄球菌 的可能性为 0.7
```
2. **推理机（Inference Engine）**：
  - 采用 **后向链推理（Backward Chaining）**，从假设目标倒推需要哪些前提条件，再向用户提问以获得数据。
3. **置信因子计算**：
  - 针对每条规则使用 01（或 -11）之间的数值表示可信度，并在规则链中进行组合运算。

> XCON/R1（1980）：DEC公司专家系统，**为 DEC 的 VAX 系列小型机自动生成计算机系统的配置方案（确定每个客户订单中需要的硬件组件及安装方法）。**每年节省约 **4000万美元；**
> 
> > 它的核心就是**把硬件专家的知识固化到规则系统中，让 AI 自动为客户装配一台完全兼容、性能满足需求的计算机系统**，而且在当时是世界上最成功的工业 AI 应用之一。 **AI装机大师**

**主要任务**：

- 输入用户的订单需求（主机型号、性能需求、终端数量等）。
- 自动确定所需的所有硬件部件（CPU、内存、磁盘、I/O 控制器等）及其兼容性，并生成物料清单（BOM）和安装连线方案。
- 确保**兼容性**和**优化配置**，减少人工配置错误。

**核心作用**：

1. **减少人工配置复杂度**：VAX 系统有成千上万种组件组合，人工配置容易出错。
2. **提高生产效率**：自动生成可直接执行的安装指导，大幅提高产线速度。
3. **降低成本**：减少配置错误和返工，节省人工成本。
4. **知识固化**：将经验丰富的配置工程师的知识固化为规则，避免人员更替带来的经验损失。

> DeepMind 是英国的人工智能公司，2014 年被 Google 收购，因研发 **AlphaGo** 打败人类围棋冠军而闻名。

### **2019 年 1 月：首次公开赛**

- **对战对象**：Team Liquid 的职业选手 **TLO**（宗族人族） 和 **MaNa**（宗族星灵）。
- AlphaStar 使用星灵（Protoss）种族作战。
- **规则**：标准《星际争霸Ⅱ》比赛规则，但 AlphaStar **视野是全地图可见**（全局信息），这点后来引发争议。
- **结果**：
  - AlphaStar 以 5:0 战绩击败 TLO。
  - 又以 5:0 战绩击败 MaNa。
  - 在比赛过程中，AlphaStar 展现出极高的操作速度（APM）和精确的微操能力，例如利用多点控制和单位规避几乎没有失误。
- **争议**：
  - AlphaStar 的全地图视野和超高反应速度被认为不是完全公平的条件。
  - DeepMind 当时承认这是初期实验，并承诺日后限制视野与反应速度，使其更接近人类体验。

conda config --add channels https://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud/conda-forge/

## 全手动安装

```shell
# 下载官方代码
git clone https://github.com/openclaw/openclaw.git

# 安装依赖
cd openclaw && pnpm install && pnpm run build

# 运行 openclaw
pnpm run openclaw onboard

# 验证安装
openclaw --version

# 环境检查
openclaw doctor

# 交互式配置向导，带你设置 API Key、连接聊天平台和初始配置。
openclaw onboard

```

安装完成后，onboard 向导会引导你完成配置。每一步的作用如下。

> 1. 选择 AI 供应商
> 
> 选 Anthropic (Claude)、OpenAI (GPT)、Google (Gemini) 或通过 Ollama 跑本地模型。
> 
> 随时可以在配置里切换。

> 1. 添加 API Key
> 
> 从供应商后台粘贴你的 API Key。Key 存在本地 .env 文件里——除了 AI 供应商，不会发到任何地方。

> 1. 连接聊天平台
> 
> 接入 WhatsApp（扫二维码）、Telegram（粘贴 @BotFather 的 Bot Token）、Discord（粘贴 Bot Token）或其他支持的平台。

> 1. 发条测试消息
> 
> 通过已连接的聊天软件给 OpenClaw 发条消息。
> 
> 如果它回复了，就说明一切就绪。试试发：'你能做什么？'

> 注意：**.env** — 所有配置存储在 `~/.openclaw/.env`。你可以直接编辑这个文件来切换供应商、添加 API Key 或调整设置。完整参考见 docs.openclaw.ai/configuration。

### 步骤四：配置 OpenClaw飞书AI助手

#### 基本整合

1. [登录云服务器实例](https://www.volcengine.com/docs/6396/67747)。
2. 执行如下命令，配置模型和飞书集成的参数。

```python
curl -fsSL https://openclaw.tos-cn-beijing.volces.com/setup.sh | bash -s -- \
    --ark-coding-plan "false" \
    --ark-model-id "doubao-seed-code" \
    --ark-api-key "请替换为方舟API Key" \
    --feishu-app-id "请替换为飞书APP ID" \
    --feishu-app-secret "请替换为飞书APP Secret"
```

> 说明：请根据实际情况，调整命令中如下参数取值：
> 
> - `--ark-coding-plan`：用于指定是否使用您订阅的Coding Plan。
>   - 若您已经订阅了Coding Plan，请传入true。
>   - 若您未订阅方舟Coding Plan，请传入false。建议您[订阅方舟Coding Plan](https://www.volcengine.com/activity/codingplan)，包月低至9.9元，模型调用自由。
> - `--ark-model-id`：用于指定您期望OpenClaw使用的方舟模型。
>   - 若--ark-coding-plan参数配置为true，请将doubao-seed-code替换为Coding Plan支持的模型名称。支持：doubao-seed-code、glm-4.7、deepseek-v3.2、kimi-k2-thinking、kimi-k2.5。
>   - 若--ark-coding-plan参数配置为false，请将doubao-seed-code替换为您期望使用的方舟模型ID。
> - `--ark-api-key`：用于指定方舟模型API Key。
> - -`-feishu-app-id`：用于指定飞书机器人App ID。
> - `--feishu-app-secret`：用于指定飞书机器人App Secret。
