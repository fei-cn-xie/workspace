## Agent Loop：智能体循环

### 基本原理

> Agent 循环包括`调用模型`、`选择要执行的工具`，然后在`不再调用任何工具时结束`：

![image.png](images/A2oXbjy6WoHbcRxCVH1cRxkUnlh.png)

> **中间件在每个步骤前后都暴露了**`钩子`

![image.png](images/WeW1bxCbLoWrUwx4FcYclsOZn6c.png)

1. 用户发起请求
  1. Agent 执行前
  2. Model 执行前
  3. Model 执行
  4. Model 执行后
  5. 工具调用；循环至 b
  6. Agent 执行后
2. 返回最终答案

四大类时机

1. Agent 前后
2. Model 前后
3. Model 执行期间
4. Tool 执行期间

### 两种钩子

> 两种方式：
> 
> 1. **Node-style hooks  节点式钩子**：在特定执行点运行
> 2. **Wrap-style hooks  包装式钩子**：在每次调用前后运行

#### Node-style hooks  节点式钩子

*📊 在线表格（无数据）*

#### Wrap-style hooks  包装式钩子

### 创建方式

> 所有中间件均可使用两个**预留参数**：  
> 
> 1. `state: AgentState`, 
> 2. `runtime: Runtime`**（短期】长期、context）**

#### 基于装饰器的中间件（写一个注解）

1. `@before_agent` - 在智能体启动前运行（每次调用执行一次）
2. `@before_model` - 在每次模型调用前运行
3. `@after_model` - 在每次模型响应后运行
4. `@after_agent` - 在智能体完成后运行（每次调用执行一次）
5. `@wrap_model_call` - 使用自定义逻辑包装每个模型调用
6. `@wrap_tool_call` - 使用自定义逻辑包装每个工具调用
7. `@dynamic_prompt` - 生成动态系统提示词

测试：

```python
from langchain.agents.middleware import (
    before_model,
    wrap_model_call,
    AgentState,
    ModelRequest,
    ModelResponse,
)
from langchain.agents import create_agent
from langgraph.runtime import Runtime
from typing import Any, Callable
from dotenv import load_dotenv
load_dotenv()


@before_model
def log_before_model(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    print(f"☀️About to call model with {len(state['messages'])} messages")
    return None

@wrap_model_call
def retry_model(
    request: ModelRequest,
    handler: Callable[[ModelRequest], ModelResponse],
) -> ModelResponse:
    for attempt in range(3):
        try:
            print(f"☀️Model call attempt {attempt + 1}/3")
            return handler(request)
        except Exception as e:
            if attempt == 2:
                raise
            print(f"Retry {attempt + 1}/3 after error: {e}")

agent = create_agent(
    model="deepseek-chat",
    middleware=[log_before_model, retry_model]
)

resp = agent.invoke({
    "messages": [{"role": "user", "content": "你好"}],
})

print(resp)
```

## 自定义 `state_schema`

如果你的中间件需要在**多个钩子间追踪状态**，可以通过**自定义属性扩展 Agent 的状态**。这使得中间件能够：

1. **跨执行跟踪状态**，如：维护在整个 Agent 执行生命周期中持续存在的计数器、标志或其他值
2. **在钩子间共享数据**，如：将信息从 `before_model` 传递到 `after_model` ，或在不同的中间件实例之间传递
3. **实现横切关注点**，如：添加如速率限制、使用跟踪、用户上下文或审计日志等功能，而无需修改核心代理逻辑
4. **做出条件决策**：利用累积状态来决定是否继续执行、跳转到不同节点或动态修改行为

### 装饰器写法

```python
from langchain.agents import create_agent
from langchain.messages import HumanMessage
from langchain.agents.middleware import AgentState, before_model, after_model
from typing_extensions import NotRequired
from typing import Any
from langgraph.runtime import Runtime
from dotenv import load_dotenv
load_dotenv()


class CustomState(AgentState):
    model_call_count: NotRequired[int]
    user_id: NotRequired[str]


@before_model(state_schema=CustomState, can_jump_to=["end"])
def check_call_limit(state: CustomState, runtime: Runtime) -> dict[str, Any] | None:
    count = state.get("model_call_count", 0)
    print(f"☀️Model call count: {count}")
    if count > 10:
        return {"jump_to": "end"}
    return None


@after_model(state_schema=CustomState)
def increment_counter(state: CustomState, runtime: Runtime) -> dict[str, Any] | None:
    return {"model_call_count": state.get("model_call_count", 0) + 1}


agent = create_agent(
    model="deepseek-chat",
    state_schema=CustomState,
    middleware=[check_call_limit, increment_counter],
    tools=[],
)

# 自定义 state 值，并执行
result = agent.invoke({
    "messages": [HumanMessage("Hello")],
    "model_call_count": 0,
    "user_id": "user-123",
})
print(f"☀️Result:  {result['messages'][-1].content}")
```

## 多中间件执行顺序

```python
agent = create_agent(
    model="gpt-4.1",
    middleware=[middleware1, middleware2, middleware3],
    tools=[...],
)
```

> 规则：
> 
> 1. `before_*` 钩子：从第一个到最后一个
> 2. `wrap_*` 钩子：嵌套（首个中间件包裹所有其他中间件）
> 3. `after_*` 钩子：从后到前（反向）

![白板](images/whiteboard_doxcn51stEtJhEnQZzA8NgZb9Ic.png)

1. **前置钩子按顺序运行**：
  1. `middleware1.before_agent()`
  2. `middleware2.before_agent()`
  3. `middleware3.before_agent()`
2.  **智能体循环开始**：
  1. `middleware1.before_model()`
  2. `middleware2.before_model()`
  3. `middleware3.before_model()`
3. **包装钩子如同函数调用般嵌套：**
  1. `middleware1.wrap_model_call()` → `middleware2.wrap_model_call()` → `middleware3.wrap_model_call()` → 模型
4. **后置钩子按****相反****顺序执行：**
  1. `middleware3.after_model()`
  2. `middleware2.after_model()`
  3. `middleware1.after_model()`
5. 代理循环结束：
  1. `middleware3.after_agent()`
  2. `middleware2.after_agent()`
  3. `middleware1.after_agent()`

## 提前跳出

要从中间件提前退出，返回一个包含 `jump_to` 的字典即可

### 装饰器写法

```python
from langchain.agents.middleware import after_model, hook_config, AgentState
from langchain.messages import AIMessage
from langgraph.runtime import Runtime
from typing import Any


@after_model
@hook_config(can_jump_to=["end"])
def check_for_blocked(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    last_message = state["messages"][-1]
    if "BLOCKED" in last_message.content:
        return {
            "messages": [AIMessage("I cannot respond to that request.")],
            "jump_to": "end"
        }
    return None
```

# Guardrails：防护栏

> 还是需要中间件

> 护栏通过在 Agent 执行的关键节点**验证和过滤内容**，帮助我们构建`安全合规`**的人工智能应用**。
> 
> 它们能够`检测敏感信息`、`执行内容策略`、`验证输出`，并在不安全行为引发问题之前加以预防。

常见应用场景包括

1. **防止个人信息泄露**： `PII`（Personally Identifiable Information） leakage
2. `检测并阻止提示注入攻击`
3. `拦截不当或有害内容`
4. `执行业务规则和合规要求`
5. `验证输出质量和准确性`

## 内置护栏

### PII detection：个人身份信息检测

> LangChain 提供了内置中间件，用于检测和处理对话中的个人身份信息（PII）。该中间件能够检测常见的 PII 类型，如电子邮件、信用卡号、IP 地址等。

**内置的 PII 类型：**

- `email` - 电子邮件地址
- `credit_card` - 信用卡号码（经 Luhn 算法验证）
- `ip` - IP 地址
- `mac_address` - MAC 地址
- `url` - URLs   `url` - 网址

**配置参数：**

```python
from langchain.agents import create_agent
from langchain.agents.middleware import PIIMiddleware
from dotenv import load_dotenv
load_dotenv()

agent = create_agent(
    model="deepseek-chat",
    middleware=[
        # Redact emails in user input before sending to model
        PIIMiddleware(
            "email",
            strategy="redact",
            apply_to_input=True, # 对用户输入进行脱敏处理。发给大模型前进行脱敏
        ),
        # Mask credit cards in user input
        PIIMiddleware(
            "credit_card",
            strategy="mask",
            apply_to_input=True,
        ),
        # Block API keys - raise error if detected
        PIIMiddleware(
            "ip",
            # detector=r"sk-[a-zA-Z0-9]{32}",
            strategy="block", # 阻止API密钥被发送到模型； 默认会报错
            apply_to_input=True,
        ),
    ],
)

# When user provides PII, it will be handled according to the strategy
result = agent.invoke({
    "messages": [{"role": "user",
                  "content":
        "我的邮箱是 john.doe@example.com，信用卡号是 5105-1051-0510-5100，"
                                             }]})

print(f"☀️Result:  {result['messages'][-1].content}")
```

### Human-in-the-loop：人工介入

> 后面我们详细演示

```python
from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import Command


agent = create_agent(
    model="gpt-4.1",
    tools=[search_tool, send_email_tool, delete_database_tool],
    middleware=[
        HumanInTheLoopMiddleware(
            interrupt_on={
                # Require approval for sensitive operations
                "send_email": True,
                "delete_database": True,
                # Auto-approve safe operations
                "search": False,
            }
        ),
    ],
    # Persist the state across interrupts
    checkpointer=InMemorySaver(),
)

# Human-in-the-loop requires a thread ID for persistence
config = {"configurable": {"thread_id": "some_id"}}

# Agent will pause and wait for approval before executing sensitive tools
result = agent.invoke(
    {"messages": [{"role": "user", "content": "Send an email to the team"}]},
    config=config
)

result = agent.invoke(
    Command(resume={"decisions": [{"type": "approve"}]}),
    config=config  # Same thread ID to resume the paused conversation
)
```

## 自定义护栏

> 对于更复杂的防护措施，**可以自定义中间件**，让其在 Agent 执行前后运行。
> 
> 从而能够完全控制验证逻辑、内容过滤和安全检查。
> 
> **总结：使用中间件方式**

### Before Agent

#### 装饰器语法

```python
from typing import Any

from langchain.agents.middleware import before_agent, AgentState, hook_config
from langgraph.runtime import Runtime
from dotenv import load_dotenv
load_dotenv()

banned_keywords = ["伊朗", "以色列", "战区"]

@before_agent(can_jump_to=["end"])
def content_filter(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    """Deterministic guardrail: Block requests containing banned keywords."""
    # Get the first user message
    if not state["messages"]:
        return None

    first_message = state["messages"][0]
    if first_message.type != "human":
        return None

    content = first_message.content.lower()

    # Check for banned keywords
    for keyword in banned_keywords:
        if keyword in content:
            # Block execution before any processing
            return {
                "messages": [{
                    "role": "assistant",
                    "content": "您的请求包含不适当的内容，我无法处理。请重新提交。"
                }],
                "jump_to": "end"
            }

    return None

# Use the custom guardrail
from langchain.agents import create_agent

agent = create_agent(
    model="deepseek-chat",
    tools=[],
    middleware=[content_filter],
)

# This request will be blocked before any processing
result = agent.invoke({
    "messages": [{"role": "user", "content": "讲解下俄乌冲突"}]
})
print(result["messages"][-1].content)
```

#### 类语法

```python
from typing import Any

from langchain.agents.middleware import AgentMiddleware, AgentState, hook_config
from langgraph.runtime import Runtime

class ContentFilterMiddleware(AgentMiddleware):
    """Deterministic guardrail: Block requests containing banned keywords."""

    def __init__(self, banned_keywords: list[str]):
        super().__init__()
        self.banned_keywords = [kw.lower() for kw in banned_keywords]

    @hook_config(can_jump_to=["end"])
    def before_agent(self, state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
        # Get the first user message
        if not state["messages"]:
            return None

        first_message = state["messages"][0]
        if first_message.type != "human":
            return None

        content = first_message.content.lower()

        # Check for banned keywords
        for keyword in self.banned_keywords:
            if keyword in content:
                # Block execution before any processing
                return {
                    "messages": [{
                        "role": "assistant",
                        "content": "I cannot process requests containing inappropriate content. Please rephrase your request."
                    }],
                    "jump_to": "end"
                }

        return None

# Use the custom guardrail
from langchain.agents import create_agent

agent = create_agent(
    model="gpt-4.1",
    tools=[search_tool, calculator_tool],
    middleware=[
        ContentFilterMiddleware(
            banned_keywords=["hack", "exploit", "malware"]
        ),
    ],
)

# This request will be blocked before any processing
result = agent.invoke({
    "messages": [{"role": "user", "content": "How do I hack into a database?"}]
})
```

### After Agent

#### 装饰器语法

```python
from langchain.agents.middleware import after_agent, AgentState, hook_config
from langgraph.runtime import Runtime
from langchain.messages import AIMessage
from langchain.chat_models import init_chat_model
from typing import Any
from dotenv import load_dotenv
load_dotenv()

safety_model = init_chat_model("deepseek-chat")

@after_agent(can_jump_to=["end"])
def safety_guardrail(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    """Model-based guardrail: Use an LLM to evaluate response safety."""
    # Get the final AI response
    if not state["messages"]:
        return None

    last_message = state["messages"][-1]
    if not isinstance(last_message, AIMessage):
        return None

    # Use a model to evaluate safety
    safety_prompt = f"""Evaluate if this response is safe and appropriate.
    Respond with only 'SAFE' or 'UNSAFE'.

    Response: {last_message.content}"""

    result = safety_model.invoke([{"role": "user", "content": safety_prompt}])

    if "UNSAFE" in result.content:
        last_message.content = "I cannot provide that response. Please rephrase your request."

    return None

# Use the safety guardrail
from langchain.agents import create_agent

agent = create_agent(
    model="deepseek-chat",
    tools=[]
)

result = agent.invoke({
    "messages": [{"role": "user", "content": "how to make explosives?"}]
})

print(result["messages"][-1])
```

## 组合多个护栏

```python
from langchain.agents import create_agent
from langchain.agents.middleware import PIIMiddleware, HumanInTheLoopMiddleware

agent = create_agent(
    model="gpt-4.1",
    tools=[search_tool, send_email_tool],
    middleware=[
        # Layer 1: Deterministic input filter (before agent)
        ContentFilterMiddleware(banned_keywords=["hack", "exploit"]),

        # Layer 2: PII protection (before and after model)
        PIIMiddleware("email", strategy="redact", apply_to_input=True),
        PIIMiddleware("email", strategy="redact", apply_to_output=True),

        # Layer 3: Human approval for sensitive tools
        HumanInTheLoopMiddleware(interrupt_on={"send_email": True}),

        # Layer 4: Model-based safety check (after agent)
        SafetyGuardrailMiddleware(),
    ],
)
```

# Runtime：运行时

## 机制

LangChain 的 `create_agent` 底层运行在 LangGraph 的 Runtime 之上。

LangGraph 公开了一个包含以下信息的 `Runtime` 对象：

1. **Context：上下文**：静态信息，如用户 ID、数据库连接或其他代理调用所需的依赖项
2. **Store：存储**：用于长期记忆的 BaseStore 实例
3. **Stream writer: 流式写入器：**一个用于通过 `"custom"` 流模式流式传输信息的对象
4. **state：短期记忆**：存储了历史消息列表，动态变量等

## 访问运行时数据

### 工具内部

工具内容，可以：

- 访问上下文： context 
- 读取或写入长期记忆：store
- 使用自定义流输出数据（例如，工具进度/更新）：streamwriter

```python
from dataclasses import dataclass
from langchain.tools import tool, ToolRuntime  

@dataclass
class Context:
    user_id: str

@tool
def fetch_user_email_preferences(runtime: ToolRuntime[Context]) -> str:
    """Fetch the user's email preferences from the store."""
    user_id = runtime.context.user_id  
    # runtime.state
    preferences: str = "The user prefers you to write a brief and polite email."
    if runtime.store:
        if memory := runtime.store.get(("users",), user_id):
            preferences = memory.value["preferences"]

    return preferences
```

### 中间件内部

```python
from dataclasses import dataclass

from langchain.messages import AnyMessage
from langchain.agents import create_agent, AgentState
from langchain.agents.middleware import dynamic_prompt, ModelRequest, before_model, after_model
from langgraph.runtime import Runtime


@dataclass
class Context:
    user_name: str

# Dynamic prompts
@dynamic_prompt
def dynamic_system_prompt(request: ModelRequest) -> str:
    user_name = request.runtime.context.user_name  
    system_prompt = f"You are a helpful assistant. Address the user as {user_name}."
    return system_prompt

# Before model hook
@before_model
def log_before_model(state: AgentState, runtime: Runtime[Context]) -> dict | None:
    print(f"Processing request for user: {runtime.context.user_name}")
    return None

# After model hook
@after_model
def log_after_model(state: AgentState, runtime: Runtime[Context]) -> dict | None:
    print(f"Completed request for user: {runtime.context.user_name}")
    return None

agent = create_agent(
    model="gpt-5-nano",
    tools=[...],
    middleware=[dynamic_system_prompt, log_before_model, log_after_model],
    context_schema=Context
)

agent.invoke(
    {"messages": [{"role": "user", "content": "What's my name?"}]},
```

# Human-in-the-loop：`HITL`（人机协同）

> **人机协同**（HITL，有些文档也叫` HIL`）中间件允许为 Agent 工具调用添加人工监督。
> 
> 当模型提出可能需要审查的操作时，例如写入文件或执行 SQL，该**中间件**可以暂停执行并等待决策。
> 
> **本质：中间件实现**

## 中断决策

中间件定义了三种内置方式，供人类在中断时进行响应：

每个工具可用的决策类型取决于在 `interrupt_on` 中配置的策略

## 配置中断

```python
import os
from typing import Optional
from dotenv import load_dotenv

load_dotenv()

# --------------------------
# 3个工具
# --------------------------
from langchain_core.tools import tool

@tool
def write_file(file_path: str, content: str) -> str:
    """
    写入文件到本地
    Args:
        file_path: 文件路径
        content: 文件内容
    """

    return f"✅ 写入文件成功：{file_path}\n内容：{content[:50]}..."

@tool
def execute_sql(sql: str) -> str:
    """
    执行SQL语句
    Args:
        sql: 要执行的SQL
    """

    return f"✅ 执行SQL成功：{sql}\n影响行数：1"

@tool
def read_data(query: str) -> str:
    """
    安全读取数据
    Args:
        query: 查询语句
    """

    return f"✅ 读取数据成功：{query}\n结果：[1,2,3,4,5]"


# --------------------------
# 官方代码：创建带 人机在环 的 Agent
# --------------------------
from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langgraph.checkpoint.memory import InMemorySaver


# 创建Agent
agent = create_agent(
    model="deepseek-chat",
    tools=[write_file, execute_sql, read_data],
    middleware=[
        HumanInTheLoopMiddleware(
            interrupt_on={ # 什么时候中断
                "write_file": True, # 所有决策 (approve, edit, reject) 都要人工审核
                "execute_sql": {"allowed_decisions": ["approve", "reject"]}, # 只允许 approve 或 reject
                "read_data": False, # 读取数据无需人工审核
            },
            # 中断消息前缀 —— 会与工具名称和参数组合，构成完整消息
            # 例如："待审批执行工具：execute_sql，查询语句为 'DELETE FROM...'"
            # 可在单个工具的中断配置中指定 description 字段，以此覆盖该前缀
            description_prefix="待审批执行工具",
        ),
    ],
    checkpointer=InMemorySaver(), # 短期记忆
)
```

## 响应中断

> 1. 执行 Agent 时，它会持续运行直至完成或触发中断。
> 2. 当工具调用匹配在 `interrupt_on` 中配置的策略时，将触发中断。
> 3. 使用 `version="v2"` 时，结果是一个包含 `interrupts` 属性的 `GraphOutput` ，该属性存储需要审核的操作。
> 4. 随后，可以将这些操作提交给审核者，并在获得决策后恢复执行。

```python
from langgraph.types import Command
# 人机协同交互机制依托 LangGraph 的持久化层实现。
# 必须提供线程 ID，将当前执行任务与对话线程相关联，
# 从而实现对话的暂停与恢复（人工审核环节需要此功能）
config = {"configurable": {"thread_id": "some_id"}}
# 运行流程，直至触发中断节点。
result = agent.invoke(
    {
        "messages": [
            {
                "role": "user",
                "content": "从 records 表中删除 id 为 1 的记录",
            }
        ]
    },
    config=config,
    version="v2",
)

# 打印中断信息，后来这些东西展示到前端
print(result.interrupts)

decision = input("请输入您的决策（approve or reject）：")


# 此处应该根据前端提交的操作，构造不同的 Command，来恢复会话
resp = agent.invoke(
    Command(
        resume={"decisions": [{"type": decision}]}  # or "reject"
    ),
    config=config, # 使用与中断节点相同的线程 ID，恢复暂停的对话流程
    version="v2",
)

print(resp)
```

## 流式输出

```python
# Stream agent progress and LLM tokens until interrupt
for chunk in agent.stream(
    {"messages": [{"role": "user", "content": "从 records 表中删除 id 为 1 的记录"}]},
    config=config,
    stream_mode=["updates", "messages"],
    version="v2",
):
    if chunk["type"] == "messages":
        # LLM token
        token, metadata = chunk["data"]
        if token.content:
            print(token.content, end="", flush=True)
    elif chunk["type"] == "updates":
        # Check for interrupt
        if "__interrupt__" in chunk["data"]:
            print(f"\n\nInterrupt: {chunk['data']['__interrupt__']}")

#
decision = input("请输入您的决策（approve or reject）：")

# Resume with streaming after human decision
for chunk in agent.stream(
    Command(resume={"decisions": [{"type": decision}]}),
    config=config,
    stream_mode=["updates", "messages"],
    version="v2",
):
    if chunk["type"] == "messages":
        token, metadata = chunk["data"]
        if token.content:
            print(token.content, end="", flush=True)
```

# MultiAgent：多智能体

> 多个智能体共同协作完成任务；
> 
> 核心机制：`主Agent` 协调**多个 **`SubAgent`，每个 `SubAgent `对于 `主Agent` 来说就**是一个工具**；
> 
> **多智能体设计的核心是**`上下文工程`**（Context Engineering）：**决定每个智能体能访问哪些信息。系统的质量取决于确保每个智能体都能获取其任务所需的正确数据。

## Subagent：子智能体

> 在子Agent架构中，**一个**`中央主代理`**（通常称为**`监督者`**）通过将**`子代理`**作为工具调用来协调它们**。
> 
> - 主代理决定调用哪个子代理、提供什么输入以及如何组合结果。
> - `子代理是无状态的`——它们不记得过去的交互，所有`对话记忆`都由`主代理`维护。这提供了`上下文隔离`：每个子代理调用都在一个干净的上下文窗口中工作，防止主对话中的上下文膨胀。

![image.png](images/V77obg9vyoSzT1x5e7rcEUU9nzd.png)

### 核心逻辑

```python
from langchain.tools import tool
from langchain.agents import create_agent

# 1. 创建子智能体
subagent = create_agent(model="deepseek-chat", tools=[])

# 2. 包装子智能体为工具
@tool("research", description="Research a topic and return findings")
def call_research_agent(query: str):
    result = subagent.invoke({"messages": [{"role": "user", "content": query}]})
    return result["messages"][-1].content
```

## Skills：技能

> `Skill（技能）`**是一种 “**`轻量级`**、**`提示词驱动`**、**`可复用`**” 的**`专业化能力封装`，核心是解决 **Agent 系统在处理复杂、多领域任务时的四大核心痛点：**
> 
> 1. `上下文过载`**：**把所有技能提示塞进同一个 prompt，内容过长
> 2. `能力分散`**：**通用 AI 什么都会一点，但样样不精通
> 3. `开发低效`**：**能力逻辑散落在代码里，难以维护和复用；如都是`AI生成SQL能力`，就共用提示词 **[技能]**
> 4. `hallucination（幻觉）增多`**：**信息混乱 + 超出能力，模型开始编造内容
> 
> 这种模式在概念上与智能体技能和`llms.txt`相同，**后者使用工具调用来逐步展示文档**。技能模式将逐步展示应用于专业化提示和领域知识，而不仅仅是文档页面。
> 
> > `llms.txt`** 是由 Jeremy Howard 于 2024 年 9 月 3 日提出的一项**`开放性提案`**，旨在为网站提供一个标准的、机器可读的入口，专门用于帮助大语言模型在推理阶段更有效地理解网站内容。**

> 1. **技能：本质上是提示词工程**。有些功能我们无需调用工具，仅通过给大模型设置提示词就可实现（比如：让大模型输出答案的时候，用`文言文风格`。 让大模型思考用户问题属于`哪种分类` 等等）
> 2. **技能：也是一种** **渐进式披露**** 机制，用来区分以前的一次性加载完整提示词。**

### 完整案例：SQL助手

> 场景：
> 
> 1. 设想构建一个智能体，用于协助在大型企业的不同业务垂直领域编写 SQL 查询。
> 2. 组织可能为`每个垂直领域`设有`独立的数据存储`，或是拥有`包含数千张表`的`单一整体数据库`。
> 3. 无论哪种情况，`预先加载所有模式都会超出上下文窗口的承载能力`。
> 4. **渐进式披露**通过仅在需要时加载相关模式来解决此问题。这种架构还使不同的产品负责人和利益相关者能够独立贡献并维护其特定业务垂直领域的技能。

> 渐进式披露由 Anthropic 推广，作为一种构建可扩展智能体技能系统的技术。
> 
> 采用三层架构（`元数据 → 核心内容 → 详细资源`），智能体仅在需要时加载信息。
> 
> **特别推荐阅读**：https://claude.com/blog/equipping-agents-for-the-real-world-with-agent-skills

![image.png](images/Ves7bvglEo1QNyxS0micefk1nDc.png)

渐进式披露优点：

1. 减少上下文使用量：仅加载任务所需的 2-3 项技能，而非所有可用技能
2. 实现团队自主性：不同团队可独立开发专项技能（类似其他多智能体架构）
3. 高效扩展：可添加数十甚至数百项技能，而不会造成上下文过载
4. 简化对话历史：单智能体单对话线程

#### 定义模型 & Skills

> **智能体****：****一个具备两种技能（**`销售分析`**和**`库存管理`**）的 **`SQL 查询`**助手**。
> 
> 1. 该智能体在系统提示中看到`轻量级的技能描述`
> 2. 然后`仅在用户查询`相关时，通过`工具调用加载完整的数据库架构和业务逻辑`。

#### 技能加载函数

`load_skill` 工具以字符串形式返回完整的技能内容，该内容将作为 `ToolMessage` 成为对话的一部分。

```python
from langchain_core.tools import tool
@tool
def load_skill(skill_name: str) -> str:
    """将技能的完整内容加载至智能体的上下文当中。

当你需要获取处理特定类型请求的详细信息时使用此功能。它会为你提供对应技能领域的全面操作指令、业务规则与指导准则。

    Args:
        skill_name：需要加载的技能名称 (e.g., "expense_reporting", "travel_booking")
    """
    # 查找并返回技能
    for skill in SKILLS:
        if skill["name"] == skill_name:
            return f"已加载 skill: {skill_name}\n\n{skill['content']}"

    # 技能未找到
    available = ", ".join(s["name"] for s in SKILLS)
    return f"Skill '{skill_name}' 没有找到. 可用的 skills: {available}"
```

#### 构建 Skill 中间件

创建自定义中间件，**将技能描述注入系统提示中。**该中间件无需预先加载完整内容即可实现技能的可发现性。

```python

from langchain.agents.middleware import ModelRequest, ModelResponse, AgentMiddleware
from langchain.messages import SystemMessage
from typing import Callable

class SkillMiddleware(AgentMiddleware):
    """将技能描述注入到系统提示词中的中间件"""

    # 将 load_skill 工具注册为类变量
    tools = [load_skill]

    def __init__(self):
        """初始化并根据 SKILLS 生成技能提示词"""
        # 从 SKILLS 列表构建技能提示词
        skills_list = []
        for skill in SKILLS:
            skills_list.append(
                f"- **{skill['name']}**: {skill['description']}"
            )
        self.skills_prompt = "\n".join(skills_list)

    def wrap_model_call(
        self,
        request: ModelRequest,
        handler: Callable[[ModelRequest], ModelResponse],
    ) -> ModelResponse:
        """同步方法：将技能描述注入到系统提示词"""
        # 构建技能附加信息
        skills_addendum = (
            f"\n\n## 可用技能列表\n\n{self.skills_prompt}\n\n"
            "当你需要处理特定类型请求的详细信息时，请使用 load_skill 工具。"
        )

        # 将技能信息追加到系统消息内容块中
        new_content = list(request.system_message.content_blocks) + [
            {"type": "text", "text": skills_addendum}
        ]
        new_system_message = SystemMessage(content=new_content)
        modified_request = request.override(system_message=new_system_message)
        return handler(modified_request)
```

注意：

1. 中间件将技能描述附加到系统提示中，使 Agent 能够了解可用技能而无需加载其完整内容。 
2. `load_skill` 工具被注册为类变量，使其可供代理使用。

> ### 生产环境优化：
> 
> 我们为简化起见，在 `init` 中加载技能列表。
> 
> 在生产系统中，建议通过 `before_agent` 钩子加载技能，以便`定期刷新技能列表`以获取最新变更（例如新增技能或修改现有技能时）。

#### 创建支持 Skill 的智能体

```python
from langchain.agents import create_agent
from langgraph.checkpoint.memory import InMemorySaver

# 创建支持 Skill 的智能体
agent = create_agent(
    model,
    system_prompt=(
        "您是一名SQL查询助手， "
        "协助用户针对业务数据库编写查询语句。"
    ),
    middleware=[SkillMiddleware()],
    checkpointer=InMemorySaver(),
)
```

1. 在系统提示中增加 技能描述访问权限 信息
2. Agent 会在需要时调用 `load_skill` 来检索完整的技能内容。
3. checkpointer机制会在多轮对话中持续维护会话历史记录。

## Router：路由【了解】

路由器对`查询进行分类`，并将其引导至适当的智能体。

使用 `Command` 进行单智能体路由，或使用 `Send` 进行并行分发至多个智能体。

```python
from langgraph.types import Command

# 问题分类，直接路由
def classify_query(query: str) -> str:
    """Use LLM to classify query and determine the appropriate agent."""
    # Classification logic here
    ...

def route_query(state: State) -> Command:
    """Route to the appropriate agent based on query classification."""
    active_agent = classify_query(state["query"])

    # Route to the selected agent
    return Command(goto=active_agent)
```

在自定义工作流架构中，可以使用 LangGraph 定义专属的执行流程。

```python
import os
from typing import TypedDict
from pydantic import BaseModel
from langgraph.graph import StateGraph, START, END
from langchain.agents import create_agent
from langchain.tools import tool
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_community.embeddings import DashScopeEmbeddings
from langchain_deepseek.chat_models import ChatDeepSeek
from langchain_core.vectorstores import InMemoryVectorStore
from dotenv import  load_dotenv

load_dotenv()

class State(TypedDict):
    question: str
    rewritten_query: str
    documents: list[str]
    answer: str

# WNBA knowledge base with rosters, game results, and player stats
embeddings = DashScopeEmbeddings(model="text-embedding-v3",dashscope_api_key=os.getenv("API_KEY"))
vector_store = InMemoryVectorStore(embeddings)
vector_store.add_texts([
    # Rosters
    "New York Liberty 2024 roster: Breanna Stewart, Sabrina Ionescu, Jonquel Jones, Courtney Vandersloot.",
    "Las Vegas Aces 2024 roster: A'ja Wilson, Kelsey Plum, Jackie Young, Chelsea Gray.",
    "Indiana Fever 2024 roster: Caitlin Clark, Aliyah Boston, Kelsey Mitchell, NaLyssa Smith.",
    # Game results
    "2024 WNBA Finals: New York Liberty defeated Minnesota Lynx 3-2 to win the championship.",
    "June 15, 2024: Indiana Fever 85, Chicago Sky 79. Caitlin Clark had 23 points and 8 assists.",
    "August 20, 2024: Las Vegas Aces 92, Phoenix Mercury 84. A'ja Wilson scored 35 points.",
    # Player stats
    "A'ja Wilson 2024 season stats: 26.9 PPG, 11.9 RPG, 2.6 BPG. Won MVP award.",
    "Caitlin Clark 2024 rookie stats: 19.2 PPG, 8.4 APG, 5.7 RPG. Won Rookie of the Year.",
    "Breanna Stewart 2024 stats: 20.4 PPG, 8.5 RPG, 3.5 APG.",
])
retriever = vector_store.as_retriever(search_kwargs={"k": 5})

@tool
def get_latest_news(query: str) -> str:
    """Get the latest WNBA news and updates."""
    # Your news API here
    return "Latest: The WNBA announced expanded playoff format for 2025..."

agent = create_agent(
    model="deepseek-chat",
    tools=[get_latest_news],
)

model = ChatDeepSeek(model="deepseek-chat")

class RewrittenQuery(BaseModel):
    query: str

def rewrite_query(state: State) -> dict:
    """Rewrite the user query for better retrieval."""
    system_prompt = """Rewrite this query to retrieve relevant WNBA information.
The knowledge base contains: team rosters, game results with scores, and player statistics (PPG, RPG, APG).
Focus on specific player names, team names, or stat categories mentioned."""
    response = model.with_structured_output(RewrittenQuery).invoke([
        {"role": "system", "content": system_prompt},
        {"role": "user", "content": state["question"]}
    ])
    return {"rewritten_query": response.query}

def retrieve(state: State) -> dict:
    """Retrieve documents based on the rewritten query."""
    docs = retriever.invoke(state["rewritten_query"])
    return {"documents": [doc.page_content for doc in docs]}

def call_agent(state: State) -> dict:
    """Generate answer using retrieved context."""
    context = "\n\n".join(state["documents"])
    prompt = f"Context:\n{context}\n\nQuestion: {state['question']}"
    response = agent.invoke({"messages": [{"role": "user", "content": prompt}]})
    return {"answer": response["messages"][-1].content_blocks}

# 工作流： 定义好节点，定义好连线，定义条件
workflow = (
    StateGraph(State)
    .add_node("rewrite", rewrite_query)
    .add_node("retrieve", retrieve)
    .add_node("agent", call_agent)
    .add_edge(START, "rewrite")
    .add_edge("rewrite", "retrieve")
    .add_edge("retrieve", "agent")
    .add_edge("agent", END)
    .compile()
)

result = workflow.invoke({"question": "Who won the 2024 WNBA Championship?"})
print(result["answer"])
```
